abap2UI5 changelog
==================

Legend
------
* : fixed
! : changed
+ : added
- : removed


unreleased
----------
+ custom control z2ui5.cc.HTMLFrame: an app's own HTML document in a sandboxed iframe (no script runs, its styles do), and the sapevent: links and the forms posted to a sapevent: action in it as the sapevent event with action, getdata and postdata - what cl_gui_html_viewer and its SAPEVENT are in the SAP GUI
* 702 build: compiles and imports on 7.02 SP13 (#2947) - no ASSERT_TRUE/ASSERT_FALSE (the downport rewrites them into ASSERT_EQUALS), no CHANGING/EXPORTING in a chained method call, no INT8, no built-in function as an INSERT operand, no line over 255 characters, z2ui5_cl_ui5_llm_guide in statements the 7.02 class scanner takes, and no GETWA_NOT_ASSIGNED dump in z2ui5_cl_ui5_srv_model at app start; npm run downport fails on these shapes from now on
+ cs_event-set_app_full_width: the app takes the launchpad's full width instead of the shell's letterbox (ShellUIService.setApplicationFullWidth from UI5 1.133, AppConfiguration before), what a Fiori elements app gets from fullWidth in its manifest - which the one z2ui5 component cannot set per app
+ cs_event-cross_app_nav_get_links: the intents the launchpad offers the user for a semantic object (getLinks), handed back to a backend event as JSON with each intent split into semanticObject, action and params - what a smart-link popover lists, navigated to with cross_app_nav_to_ext
- the eight obsolete invisible custom controls z2ui5.cc.Timer, Focus, Scrolling, Title, LPTitle, Favicon, History and Info (deprecated in #2789) - a view that still names one fails to load; the replacements are the frontend actions cs_event-start_timer, set_focus, scroll_to / scroll_into_view, set_title, set_title_launchpad, set_favicon, hash_set( ) / app_state_set_active( ) and client->get( )-s_device / -s_ui5
* z2ui5_cl_ui5_user_exit=>set_instance( ): a subclass of the shipped exit is installed as the shipped exit, not as a customer exit the shipped set_config_http_get/post dispatch to - a subclass that did not redefine both methods recursed into itself and dumped on the first request
* a roundtrip of an app that is not sticky and raises in main( ) rolls the app's LUW back before the 500, with or without a monitor installed - the end of the ICF dialog step committed what the app had written before it raised
* set_session_stateful( abap_false ) followed by an exception in the same roundtrip: the sticky flag goes back to the request's start state, so the next event no longer runs on a stateless handler against a draft that was never written
* a bookmark restore (z2ui5-xapp-state) clears id_prev_app together with the app stack - get_app_prev( ) no longer follows a draft of the session the bookmark was made in
* Content-Security-Policy: the shell's script hash is added per directive - an exit that listed it in script-src no longer kept script-src-elem from getting it, which blocked the inline boot script
* z2ui5_cl_ui5_view_builder: a name ending in a colon or with a second colon (xmlns:, a::b) raises instead of rendering a view no XML parser reads
* z2ui5_cl_ui5_util_context=>c_escape_xml( ): U+FFFE and U+FFFF are dropped like the control characters; conv_decode_x_base64( ) / conv_encode_x_base64( ) re-raise a failing fallback with its cause
* z2ui5_cl_ui5_llm=>create_openai( ): a response whose content is null and whose message carries a refusal raises z2ui5_cx_ui5_llm as a refusal instead of "returned no text"
! nav_app_call to an app that only opens a popup: the caller's keyboard shortcuts, tree and table snapshots, model size limits and hash listener survive the hop - the frontend reset them whenever the response named another app, now only when the response replaces the app on MAIN
* Developer tools: Escape runs the dialog's close on UI5 1.71 (the escapeHandler is set in code; as an XML attribute the property is typed any there and stayed a string), so the error popup the Details action came from is shown again
* handler-queued frontend actions resolve their ${/path} arguments against the model of the slot the responding app filled, not always MAIN
- the "No internet connection" alert on an event while navigator.onLine is false - it silenced every timer tick on an intranet host the browser reports as offline; a network failure is reported by the roundtrip itself, with Retry
* Developer tools: the ABAP source and ADT links use the origin of the endpoint, not of the host page, when the component is embedded
+ release assets: backend-<version>.tar.gz.sha256 next to the prebuilt backend, verified by @abap2ui5/mcp-server
+ cs_event-offline_queue (experimental): the events an app names wait in the browser while the backend cannot be reached - kept with their model changes across a reload, sent in order once the network is back, each on the draft the previous one left; every other event fails as before. The page itself still needs the network to load (docs/concepts/offline.md)
+ release assets: abap2ui5-<version>.cdx.json, the CycloneDX bill of materials of the release - the ABAP objects and the embedded frontend with a SHA-256 each, and UI5 as the one runtime dependency, never bundled (npm run sbom; check:sbom holds the tree to "nothing third-party is shipped")
+ z2ui5_cl_ui5_llm=>guide( ): the guide to building apps (docs/agents/building-apps.md) ships in the system, in the version of the release installed - for a model that writes apps and for the AI assistants that read the system's code rather than the repository. Generated into z2ui5_cl_ui5_llm_guide by npm run guide-class
! automatic model update: the pre-main( ) snapshot the handler compares against is a copy of the bound values (table sharing makes it free for everything main( ) leaves alone) instead of a digest of the serialized model - a delta roundtrip no longer serializes the whole model before main( ) runs, and an event roundtrip without a display serializes it only when it will be sent. The digest the draft carried for it (mv_model_client_hash) is gone: a draft written by the previous release does not deserialize any more, the roundtrip on it answers the error page once and the next start is a fresh app. z2ui5_cl_ui5_util_context=>hash_string( ), which existed for that digest, is removed
* z2ui5_cl_ui5_view_builder: an element or attribute name starting with a colon, and a prefixed name next to ns (ele( n = `x:Icon` ns = `core` )), raise instead of rendering a view no XML parser reads
* z2ui5_if_ui5_llm: a temperature with a leading or trailing point (`.7`, `1.`) is refused before the request instead of going out as invalid JSON
* message box and error texts: an int8 value is printed, with its sign in front
* Developer tools: the Journey export no longer cuts a long literal inside a doubled backtick, and a Copy button pressed twice returns to its label
* ExcelBridge: a text like 2024-13-01 or 2024-01-15T10:75:00 stays text instead of becoming a rolled-over date
+ Developer tools: the Journey tab (Roundtrips, key JOURNEY) records a click-through - every roundtrip as a step with the event, its arguments, the model delta the user typed and the screen the response showed - and exports it as an ABAP Unit test class that replays the journey on z2ui5_cl_frontend_simulator (abap2UI5/headless-frontend): set_value / set_json / set_cell for the typed values, click for the event, assertions on the messages, layers, control ids and events of the screens reached. Paste it into the app's test include
+ z2ui5_if_ui5_llm: one language model seam for apps and addons - chat( ) with system prompt, conversation and options, answering text, stop reason and token usage, raising z2ui5_cx_ui5_llm; providers from z2ui5_cl_ui5_llm: create_claude( ) (Messages API), create_openai( ) (Chat Completions: OpenAI, Azure OpenAI, Ollama, LM Studio, gateways) and create_local( ) (rule-based, no HTTP, for 7.02 and tests). Keys, models and endpoints come from the app
+ z2ui5_cl_ui5_util_http=>client_request( ): outbound HTTP with header fields and a timeout, on Standard (CL_HTTP_CLIENT) and on ABAP Cloud (CL_WEB_HTTP_CLIENT_MANAGER), both named dynamically; client_call( ) goes through it and so reaches ABAP Cloud as well
! frontend/embed (the delivery branches standard_new and cloud_new): @abap2ui5/embed-control 0.3.0, and the page is handed to the app by the control's ownsPage, set in the view - the controller no longer probes the control for ownsPage or its older name ownsHash
+ coding agents: the abap2UI5 plugin for GitHub Copilot in plugin-copilot/ (copilot plugin install abap2UI5/abap2UI5:plugin-copilot) - the four skills, the five commands (also as VS Code prompt files), the abap2ui5-reviewer custom agent and the MCP server - and the four skills in the Agent Skills format in skills/ (npx skills add abap2UI5/abap2UI5), both generated from the Claude Code plugin's sources


2026-10-14 v1.148.0
-------------------
! @abap2ui5/node-runtime: @abaplint/transpiler-cli and @abaplint/runtime 2.14.5, open-abap-core 9c1271b. The runtime brings ASSIGN COMPONENT of a component whose name has a dash (abaplint/transpiler#1996), rescale( ) (#1997) and CREATE DATA ... TYPE (name) with a lower-case type name (#1998); open-abap-core cl_abap_refdescr=>create( ) with kind and type kind (open-abap/open-abap-core#1310), cl_abap_tstmp=>add( ) / subtractsecs( ) keeping the fraction of a timestampl (#1311), describe_by_data( ) of a REF TO data without a runtime type (#1312) and the sXML JSON reader delivering duplicate keys in document order (#1313). Eight framework unit tests that were skipped on Node run there now
! @abap2ui5/node-runtime: abap2ui5-transpile transpiles the framework and your classes together - BREAKING for a host that loads apps/index.mjs. npx abap2ui5-transpile abap abap2ui5 transpiles the package's downport/, open-abap-core and express-icf-shim at the commits the package records (abap2ui5.openAbapCore, the new abap2ui5.expressIcfShim) and your classes in one run, with the transpiler the package names, into abap2ui5/: a complete runtime of your own with the layout of the package's output/, and a host.mjs in it - the package's exports, running on that output. import { serve } from "./abap2ui5/host.mjs" instead of from "@abap2ui5/node-runtime"; there is no apps/index.mjs to import any more. Your classes no longer load on the package's output/ through rewritten imports: one transpile with one transpiler version, as the transpiler's maintainer asked for in abaplint/transpiler#1999. Your tables are created in the SQLite database like the framework's. A process runs one output - importing the package next to an output's host.mjs is refused before it would load a second runtime. About ten seconds for the framework's thousand objects. --shim names an express-icf-shim checkout of your own, like --core; --keep and the apps folder are gone
! @abap2ui5/node-runtime: abap2ui5-own-apps is deprecated - "Your own apps" no longer uses it; it stays, unchanged, for the hosts that call it
! @abap2ui5/node-runtime: srv/host.mjs is srv/hostcore.mjs bound to output/ (srv/framework.mjs, srv/claim.mjs) - the exports and their behaviour are unchanged, importing the package still boots output/
