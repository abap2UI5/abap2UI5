abap2UI5 changelog
==================

Legend
------

unreleased

! Model: a bound standard table of flat rows (every cell an elementary type: character, numeric text, string, binary, date, time, every numeric kind, abap_bool and its DDIC twins) and a bound flat structure are written to JSON directly (z2ui5_cl_ui5_srv_model=>attri_json_fast) and spliced into the stringified tree, instead of one ajson node per cell - byte for byte what ajson writes under the upper-case mapping (keys upper-cased and in ajson's order, the same escaping, every kind rendered through the same |{ }|), the test class holds the two side by side for every kind. Dates and times as ajson's ISO text. Everything else (a nested structure or table in a row, a column typed timestamp, a sorted or hashed table, a table of scalars, an include, _bind( json ), a custom mapper or filter) stays on ajson. Measured on the transpiled runtime at 4000 rows of three columns: the start roundtrip 1.1 s to 0.6 s, the event roundtrip 2.2 s to 1.7 s
! Frontend: the UI5 version info (S_UI5) travels alone on the first roundtrip that finds it loaded. The first roundtrip of a page load fires before VersionInfo.load answers - on purpose, the first paint does not wait for a network fetch - and the session block used to count as unsent while S_UI5 was missing, so the second roundtrip of every page load repeated the device profile and the launchpad ComponentData. core/Session.js latches the static blocks on their own and sends S_UI5 by itself once it is there; z2ui5_cl_ui5_handler=>session_merge merges a request carrying S_UI5 without the device block into the stored block instead of replacing it (which wiped the device profile with an empty one)
+ GET shell: two <link rel="preconnect"> hints to the UI5 origin (one per connection pool, with and without crossorigin) in the head when the bootstrap src is an absolute URL - the bootstrap tag sits below the embedded preload, so without the hint the DNS lookup and the TLS handshake to the CDN started only once the parser got there. Outside the inline script, so its CSP hash is unchanged; nothing for a relative src (a UI5 served by the system itself). No preload of the theme stylesheet: its URL is not derivable reliably across versions and configurations (the sap-ui-cachebuster segment, RTL, theme roots)
! Draft: the model the client was left holding is stored as its SHA-256 digest (z2ui5_cl_ui5_app_cont=>mv_model_client_hash, through the new z2ui5_cl_ui5_util_context=>hash_string - cl_abap_message_digest named dynamically, the text itself where no digest class answers), not as the JSON text. Its one use is the equality with the model main( ) leaves behind, and the text was the largest part of every draft: at 4000 bound rows the draft row went from 439,796 to 267,055 characters, 61,977 to 31,719 bytes gzipped, written and read back on every roundtrip
! z2ui5_cl_ui5_util_json_fl=>mapper_upper( ): the upper-case field mapping is implemented by the class itself - to_upper( name ) and nothing else. ajson's create_upper_case( ) answered the same name through a field mapping (to_upper, a READ on an always-empty field table) and a second to_upper, three calls and a table read per node name on every cell of every bound table; ajson is untouched, the output is byte for byte the same (the test class holds both side by side)
! Frontend: the developer tools are out of the GET shell. The dialog, its fragment, the inspectors, the tabs, the picker, the live editor and the report are a second generated bundle (z2ui5_cl_ui5f_preload=>get_devtools), served on GET <node>?z2ui5-bundle=devtools (z2ui5_cl_ui5_http_handler=>_http_get_devtools - as JavaScript, with an ETag of its own and a 304) and loaded by the frontend with a <script> element the first time the tools are opened (Ctrl+F12, the auto open, the Details of the error overlay); the facade, the console capture and the roundtrip recorder stay in the shell, as they have to run from the first roundtrip on. The shell went from 426,018 to 338,840 bytes uncompressed, 98,177 to 76,708 gzipped (the devtools bundle: 89,749 bytes, 22,494 gzipped); no inline script and no eval - the default CSP is unchanged. The ?z2ui5-bundle of a page that embeds the component is slimmer by the same files, and an embedded app loads the devtools bundle from its endpoint the same way
! Frontend: the libraries a view or fragment names (xmlns) are loaded as their preload bundles before the view is built - sap.ui.table, sap.uxap, sap.f, sap.ui.layout, sap.ui.unified, sap.suite.ui.commons, sap.ui.codeeditor and every other library manifest.json does not declare. UI5 resolved their controls module by module (a view with one sap.ui.table.Table: 37 requests, 308 ms at 40 ms round-trip time; 8 requests, 158 ms with the bundle). Each namespace is mapped to its library through sap-ui-version.json (sap.ui.layout.form is a namespace of sap.ui.layout), a library loaded already is skipped, and what was tried is remembered for the page (core/Env.js loadViewLibraries)
! Frontend: a view_display( ) without a transition builds the new MAIN view while the old one stays on screen, and destroys the old one once the new one rendered. The old page was destroyed before the build - the screen was blank for the whole build (the destroy, the XML processing, a library load), and the destroy sat on the critical path; the page change with a transition already did it this way, and the plain swap now builds under the alternate view id the same way (mainView / mainView2 - never spell the id, ask the slot)
! Frontend: the request size the developer tools show as REQ is counted on the first call, not on every request. Server.readHttp copied the whole serialized body into bytes (TextEncoder.encode) on every roundtrip for the one reader that wants the number - the recorder, which is not installed on most pages; state.lastRequestBytes is a function now (Lib.lazyByteLength) and the recorder calls it
! @abap2ui5/node-runtime: initialize() installs the host's seams once - the user exit through the new z2ui5_cl_ui5_user_exit=>set_instance( ) (the shipped defaults, or initialize({ exit }) with a transpiled exit class of the host's own, called through the shipped exit like a customer exit on a system), where the class lookup raised on every get_instance( ) of every request before; and zcl_serializer_live as the draft serializer, so the draft row carries an id and the app container stays live behind it instead of being walked into asXML and back on every click. An id answers the app as it is now (the semantics of a stateful session, for every app of a Node host); initialize({ draftSweepMs }) arms a timer that sweeps the expired table rows and containers (sweepDrafts(), configureDraftSweep(), five minutes by default, unref'd)
! z2ui5_cl_ui5_srv_bind: the standard-table verdict of a cell bind is memoised with the component names of the table, and a re-bind that carries a mapper or filter asks no class name for the same instance and only once per service for the stored one
! @abap2ui5/node-runtime: @abaplint/transpiler-cli and @abaplint/runtime 2.14.2, and output/ in the layout 2.14 writes - BREAKING for code that imports a module of output/ by path. Every module now sits in a folder per origin: output/project/ (the framework and ZCL_SICF), output/open-abap-core/, output/express-icf-shim/; init.mjs stays at output/init.mjs. An import of @abap2ui5/node-runtime/output/cx_root.clas.mjs becomes .../output/open-abap-core/cx_root.clas.mjs, of .../output/z2ui5_cl_ui5_http_handler.clas.mjs .../output/project/z2ui5_cl_ui5_http_handler.clas.mjs. abap2ui5-own-apps and abap2ui5-transpile take the host's classes from output/project/ and point their imports at the package's module of the same name in whichever folder it is; the package records @abaplint/transpiler-cli 2.14.2. own-apps also reads the flat output of an earlier transpiler (abap2UI5/protocol's conformance host transpiles with 2.13), and in output/project/ refuses a class of the host's with the name of one of the package's. The runtime brings d and t assigned to a number as a day count (abaplint/transpiler#1977) and method parameters TYPE p as packed (#1971). The release tarball backend-<version>.tar.gz carries node/output/ in the same layout
! _bind( omit_initial = abap_true ) and omit_initial_paths drop an abap_false as documented. ajson writes it as the literal false, which the emptiness test never counted as initial - an app that needs that false to arrive lists only its other columns in omit_initial_paths
! z2ui5_cl_ui5_view_builder: an element or attribute name must be an XML name (ASCII letters, digits, _ . - :, not starting with a digit, . or -), and a ns ending in a colon is refused. te(xt or 1st passed and broke the view in the browser; ns = `core:` rendered core::Icon
! follow_up_action( ) from a handler: an argument that is exactly ${/X} (or ${http>/X}) is read from the model, as on a view wire. It reached every action as that text - BINDING_CALL cleared a bound filter, CROSS_APP_NAV_TO_EXT started the target without its parameters, URLHELPER opened an empty mailto:
* cs_event-bind_element: an empty, non-integer or negative row index is logged and the view not rebound, instead of binding it to "<path>/"
* Event arguments: a binding context (${$parameters>/rowContext}), a plain object holding controls and $event itself travel as JSON ({ PATH, OBJECT } for a context, { ID, SOURCE, PARAMETERS } for an event) instead of failing to serialize; a body that cannot be serialized is reported as such, without a Retry that could never work
* Server: a timeout while the response body is read is reported as the timeout, with Retry; an HTML page answered with 2xx (a logon page after the session expired) and a response without S_FRONT get messages that say what to check; a fetch that reaches no backend names the usual causes
* Model: a date or time cell that is neither ISO nor digits (15.01.2024) is refused and listed in t_model_skipped instead of stored cut to its first 8 or 6 characters; a delta for a row past the end of the table is listed there too instead of dropped silently
* _event( t_arg ): an argument that looks like an expression but has unbalanced braces ({, {0, ${x) is quoted instead of breaking the handler
* cs_event-download_b64_file: a data: URL with an active type (text/html, svg, xml) is refused also when written with leading whitespace, a tab in the scheme or a blank after data:
* Custom control z2ui5.cc.ExcelBridge: a time cell in Excel's own time format ([$-x-systime]h:mm:ss) is read as a time, not as a 1899-12-30 date-time; a column named constructor or toString no longer reads an inherited member
* Custom control z2ui5.cc.MultiInputExt: free text with braces or a backslash becomes a token as typed on every release (on 1.71 "{a}" became a binding)
* Custom controls: Geolocation sends no NaN heading and falls back to the default for an unusable timeout; Focus and SET_FOCUS ignore a non-numeric caret position; the FileUploader button text is shown as written
* Date formatters: a year below 100 is no longer read as 19xx, and an impossible day (20240230) gives no date instead of rolling over
* z2ui5_cl_ui5_util_context: c_trim removes any depth of space/tab padding; itab_get_by_struc writes negative numbers with a leading sign; itab_filter_by_val with an empty search keeps every row
* Start page: Check with an empty input asks for a class name; the "class does not exist" message stays visible when the user exit hides error details; the system popup shows "none (shipped defaults)" without a user exit
* Draft buffer: loading an app that another instance had buffered under the same draft id replaces the entry instead of parsing the draft again on every load
* Response: a bound value carrying a control character other than tab, line feed and carriage return (U+0001, a form feed out of a legacy long text) leaves as a \u00XX escape. It left raw - of the control characters ajson escapes only those three - and the browser's JSON.parse refused the whole response
* client->message_box_display( ) with a message table: the box takes its type and title from the most severe message (error, then warning, then success or information), not from the first - [W, E] opened as a warning. The headline reads "2 Messages found:" without the blank on either side
* Request: a device size, caret position or scroll offset the browser writes in a form type i cannot take (1e10, 1e-7) is read as 0 instead of ending the roundtrip in a 500
* Keyboard shortcuts (cs_event-keyboard_shortcut): a key the keyboard layout only types with Shift - Ctrl++ and ? on a US layout, the digits on AZERTY - fires its shortcut. The keydown carried the Shift and never matched the registered combination; a letter keeps Shift apart (Ctrl+Shift+S is not Ctrl+S) and an explicit Shift+ registration still wins
* Custom control z2ui5.cc.MessageManager: a row with an empty TYPE is shown as an error, as intended. ABAP sends the unfilled column as an empty string, which never reached the default and became a message of type None
* cs_event-filter_bar_variant_init: the filter count of the bar includes a filled filter of the basic group (filterItems). Only the filterGroupItems were counted, although the variant stored both
* Custom control z2ui5.cc.ExcelBridge: a cell with an elapsed-time format ([h]:mm:ss, [mm]:ss) or a minutes:seconds format (mm:ss) is read as a time - an elapsed one as a duration whose hours run past 24 (36:00:00) - instead of the bare serial number
* Start page: a successful Check after a failed one drops the old error text from the class name input
* filter_get_token_t_by_range_t (z2ui5_cl_ui5_util_context): LOW and HIGH go into the token as written. A LOW that spelled {HIGH} was substituted a second time, and under the transpiled runtime a $& or $$ in a value was read as a replacement pattern
* Custom controls z2ui5.cc.FileUploader and z2ui5.cc.CameraPicture write the read file and the captured photo without re-rendering the control - the renderer draws neither
* Keyboard shortcuts (cs_event-keyboard_shortcut): the value still being typed in the focused field travels with the shortcut's event. A text field writes its value on change - blur or Enter - and a Ctrl+S or an F-key pressed while typing came first, so the save ran on the old value. The field is committed the way leaving it would; when its change is itself wired to the backend, the shortcut's event follows that roundtrip instead of being dropped
* Message box and toast: the onclose event of client->message_box_display( ) and message_toast_display( ) reaches the backend also when the user closes the box while another roundtrip is running - a timer poll, a click. It went into the busy guard and was dropped: the answer to "Delete?" never arrived. It now waits for that roundtrip and follows it
* Nested views: a second nested view placed inside the first (nest2_view_display with a parent of the first nested view) is cleared with it when the first is displayed again. It stayed registered as a destroyed view, so its scoped keyboard shortcuts still fired and the developer tools still listed it
* cs_event-clipboard_copy: a text that is valid JSON is copied as that JSON text. The backend embeds such an argument as an object, and the clipboard received "[object Object]" - an app's "copy as JSON" button copied that
* Custom controls z2ui5.cc.NativeBridgeScan and z2ui5.cc.CameraPicture render a DOM root of their own around their button. Without one UI5 could not find them again to re-render: a later change of text, enabled, visible or width from the model never reached the screen, and a scan button bound to enabled = false still started a scan
* Custom control z2ui5.cc.CameraSelector reads the cameras again when its dropdown opens and when the browser reports a device change. Read once at start - before the camera permission, when a browser lists each camera without id or label - it kept a single blank entry for good. A camera label is shown as written; one with braces lost them
* client->nest2_view_display( id = ... ) finds a control of the first nested view, as documented. The parent was looked up in the main view only, where the nested view's controls are not found - the display was discarded with "parent control not found"
! z2ui5_if_client documentation: message_box_display( ) without actions shows UI5's default for the type (CLOSE for error, OK and CANCEL for confirm) - not OK alone; its details are shown unfolded, not behind a link; nest_view_display( method_destroy ) removes the control's other content - the previous nested view goes on every call anyway; and the hash and app-state cs_event constants are options of the response that do not run wired into a view
* Message box: a title or a button text with braces is shown as written. client->message_box_display( ) handed both to UI5 as settings, which it reads as binding syntax - "Total {net}" came out empty and "Price {net" threw, so the box never opened. The pressed action still goes back to the app as it was sent
* User exit: a lookup of the exit class that failed - a transient repository error - is asked again on the next request, as its comment promised. The instance it left behind ended the lookup for the rest of a sticky session, which then ran on the shipped defaults instead of the installed exit's settings
* Fiori Launchpad: closing an abap2UI5 component no longer clears the launchpad's dirty flag. The component wrote false on every exit, after cc/Dirty had re-synced the flag from the unsaved changes that remain - a second component's unsaved changes lost their data-loss prompt, and an embedded component cleared the flag of the app hosting it
* Fiori Launchpad: unsaved changes marked with z2ui5.cc.Dirty before the shell's UI service had loaded reach the launchpad's dirty flag once it is there. The mark armed the browser's own prompt only, and a navigation inside the launchpad lost the changes without asking
* Model: an empty TIMESTAMP or TIMESTAMPL that the user never touched is no longer refused. ajson writes it as 0000-00-00T00:00:00Z, an edit of a sibling field sends the structure back whole, and read as an instant the value was nothing - so every roundtrip listed the untouched field in t_model_skipped, which an app that checks the list for a complete write-back reads as a failed save
* Navigation: client->nav_app_call( ) with an app instance that is already on the app stack - nav_app_call( me ), or a called app calling its caller back instead of leaving - makes it a new stack entry. Its own draft was reused: the stack then pointed at itself or round in a circle, Back never reached the first app again and check_app_prev_stack( ) stayed abap_true
* filter_get_token_t_by_range_t (z2ui5_cl_ui5_util_context): a range on a numeric field gives tokens with the number as it reads - =42 and -5...10, not =42 with a trailing blank and 5-...10
* _bind( val = ... json = abap_true ): a string that holds no JSON yet - initial, or cleared - travels as null. It was refused like a broken one, and since the model is serialized on every roundtrip, the app failed with "Json parsing error" on every request until the string was filled (a card manifest loaded later)
* View builder: a NUL character (U+0000) in an attribute value is dropped with the other control characters XML 1.0 cannot carry. It stayed in the view, and the browser's XML parser refused the whole view
* MessagePopover link policy RELATIVE_ONLY (CONTROL_BY_ID setAsyncURLHandler) asks the URL parser whether a link leaves the app. A pattern on the spelling let through what the browser reads as another host or scheme - /\evil.com, \\evil.com, a leading control character, a line break inside javascript: - and a message description could carry a working link off the site
* URLHELPER REDIRECT with NEW_WINDOW opens the target with noopener,noreferrer. URLHelper.redirect opens it without on UI5 1.71 - 1.83, and since this redirect may leave the origin, the foreign page got window.opener and could navigate the app's tab
* Error dialog: an error text with braces - a JSON snippet, a binding error - is shown as it is. Each line was handed to its Text as a setting, which UI5 reads as binding syntax: {...} vanished, {= } was evaluated, and an unbalanced { threw, so the user got the raw fallback overlay
* Start page: the sample repository links are written as literal values. They carry the page's own query and hash, where a browser leaves { and } unencoded, so a crafted link read them as a binding and could break the start page
* Message box: data with a column called ID - the key of most business tables - is shown as data again. client->message_box_display( ) took any ID for a T100 message class, assembled `I:0001:` per row and showed "2 Messages found" instead of the table; a message is built from a class only together with its number now
* Message box: a negative number shown as data carries its sign in front - -5, -12.50 - instead of behind it (5-, 12.50-)
* check_queue_last: a keystroke typed into a popup that the response then closed is dropped, as documented. The popup's controller outlives the popup, so the check let it through, and an event for a closed screen went out without a model
* Developer tools: the history and the Log tab record the messages of message_toast_display and message_box_display - only the rarer follow_up_action( control_global ) form was read. The model diff compares the last two responses that carried a model; a roundtrip that changed nothing showed the whole previous model as removed. The Registry tab lists an eF( 'CONTROL_BY_ID', ... ) under its own name instead of under the event of a later eB, which went missing
* Custom control z2ui5.cc.UITableExt: the column filters and the sort order are re-applied after a view_display - its main case. The snapshot was kept on the companion control, which the rebuild destroys with its view; the new one had read nothing and applied nothing, and the table came back unfiltered and unsorted. It is kept on the component's context now, like cc/Tree's expansion, and dropped on an app switch
* File uploads (z2ui5.cc.FileUploader, z2ui5.cc.UploadSetExt): a file that finishes reading while another roundtrip is running - a click, a timer tick, a websocket message - waits for it. Its event went into the busy guard and was dropped, and the next file overwrote it: of three files picked, one could silently never arrive
* Custom control z2ui5.cc.MultiInputExt: a token built from a picked suggestion row or item takes the cell text as it is. Handed to the Token as a setting, the text was read as binding syntax - "Pump {X}" lost its {X}, "A{1" threw and the pick made no token at all, a backslash disappeared
* Navigation: a bound value the caller changed right before nav_app_call reaches the browser on the way back, also when the request that made the hop carried user input. That input cleared what the framework remembers of the browser's model, the hop saved the caller without it, and on the way back the caller's current state counted as what the browser shows - a caller that left its view standing and re-displayed nothing kept showing the old value
* Model: an instant with a fraction of a second bound to a short TIMESTAMP is cut to its second. The assignment rounded it, and 12:30:59.6 became 20240115123060 - second 60, a value no timestamp has. A TIMESTAMPL keeps the fraction as before
* client->get_app( client->get( )-s_draft-id ) answers the running app. That id is the one of the roundtrip in progress, whose draft is written only when it ends, so the call raised NO_DRAFT_ENTRY_OF_PREVIOUS_REQUEST_FOUND for an id the interface documents
! z2ui5_if_client: the documentation of app_state_set_active and app_state_get_href says what a shared link does. A draft belongs to the user who created it and expires after a few hours, so the link restores the state for that user; another user, or a link whose draft is gone, starts fresh with a toast. It promised that a shared link restores the exact state for anyone
* Developer tools: the console log and the roundtrip history are carried across a reload again. The component's own pagehide listener tore the component down first, and its exit took the tools' pagehide listeners off before they had run - only a page entering the back/forward cache ever kept them
* Formatters: DateAbapDateToDateObject and DateAbapDateTimeToDateObject read a date bound straight from a DATS field - the model carries it as YYYY-MM-DD, and it always came out as no date - and a TIMS time as HH:MM:SS, which came out as an Invalid Date. DateCreateObject reads a bare YYYY-MM-DD as the local day; it was UTC midnight, the previous day anywhere west of Greenwich
* Model size limits: a limit an app set with cs_event-set_size_limit no longer applies to the next app after a navigation - the new app's tables were capped by a limit it never asked for
* @abap2ui5/node-runtime: abap2ui5-transpile runs the transpiler through npx on Windows. Without @abaplint/transpiler-cli in the project it stopped with spawnSync npx.cmd EINVAL - Node refuses to start a .cmd without a shell
* @abap2ui5/node-runtime: abap2ui5-own-apps no longer copies the libraries' source maps into the host's apps folder. The package ships its output without maps, so every library map of the host's transpile was taken for the host's own - some 470 files
* Keyboard shortcuts: a shortcut registered for the POPUP or POPOVER slot (follow_up_action( cs_event-keyboard_shortcut ) with that scope) sends the dialog's model. It ran on the MAIN controller that registered it and sent the MAIN view's edits only, so what the user had typed into the dialog did not reach the backend - the dialog's own Save button sent it
* Messages: RAP rows carry their element and action again (t_meta element / action). %ELEMENT-<field> and %OP-%ACTION-<name> were looked up among the row's own component names, which never contain a `-` - they are components of the nested structures %ELEMENT and %OP-%ACTION - so neither was ever found
* Messages: the types A (abort) and X (exit) are shown as errors, not as information
* Messages: a structure with a plain field named ITEM - a position number - is no BAPI envelope. Its ITEM value became the whole message and the other fields were dropped; only an ITEM that is a table, a structure or an object is followed now
* Custom control z2ui5.cc.ExcelBridge: text that only begins with an ISO date ("2024-01-15 delivery", a document number "2024-01-15-0001") is written as text. It was written as that date and the rest of the text was lost. A timestamp with fraction, Z or offset is still a date
* Custom control z2ui5.cc.ExcelBridge: available turns true when the host page loads Office.js after the control's first rendering, on its next rendering. It was asked once, and stayed false for the life of the control
* Custom control z2ui5.cc.Focus: the caret of the field the user just left is no longer applied to the field the backend moves the focus to. It overrode the requested selection - a select-all came out as a caret at the end
* Custom control z2ui5.cc.CameraPicture: cancelling the camera dialog while the browser's camera permission prompt was still open and opening it again left the first camera stream running once access was granted - until the page was closed. The stream of an earlier opening is stopped now
* Binding: a structure with an INCLUDE TYPE ... RENAMING WITH SUFFIX can be bound. Its components are named <component><suffix>, but the framework's component list reported the bare include names, so every binding below such an attribute failed with "No class attribute for binding found" - and since the failed lookup aborted the whole pass, so did the bindings of unrelated attributes sorting before it; a table whose row type has such an include failed the same way for its cells
* Draft restore: a REF TO data component of a structure that a generic reference aliases (mr_alias = REF #( ms_nested ), ms_nested-r_val a REF TO data) keeps its target. The restore followed the component's row under the alias like an alias of its own, and once mr_alias pointed at ms_nested again both sides named the same variable - r_val came back pointing at itself and its value was gone. It happened when the draft was saved by the roundtrip that first saw the attributes (an app that had not bound anything yet)
* App state: a bookmark #/z2ui5-xapp-state=<id> restores its app also when the URL carries no ?app_start= - client->app_state_get_href( ) keeps the page's own query, and an app reached by navigation (from the start page, by nav_app_call) has none, so the link opened the start page and dropped the saved state without a word. When the draft is gone such a link lands on the start page with the "Bookmarked app state expired" toast
* Hash navigation: the HASH_BACK frontend event with a fallback hash takes the fallback once every hash this page load pushed has been stepped back over. It counted pushes and never Back steps, so on a page opened from a bookmark the second in-app Back called history.back( ) and left abap2UI5 instead of going to the fallback
* Event arguments: a Date passed on its own - ${$parameters>/startDate} of SinglePlanningCalendar.cellPress, the from of DateRangeSelection.change - arrives as its local day (2018-07-09T00:00:00), as a Date property of a control already did. It went out as the UTC instant (2018-07-08T22:00:00.000Z), so east of Greenwich an app reading the first ten characters got the previous day
! Roundtrip monitor: off until the user exit switches it on. z2ui5_if_ui5_exit=>ty_s_http_config_post has a new field check_monitor_active, abap_false by default; only when set_config_http_post sets it to abap_true does abap2UI5 look up and call a class implementing z2ui5_if_ui5_monitor.
