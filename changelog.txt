abap2UI5 changelog
==================

Legend
------
* : fixed
! : changed
+ : added
- : removed



unreleased
----------
! The draft is written with one database statement per roundtrip instead of two: create( ) inserts first and asks who owns the row only when the key already exists (the SELECT that guarded a MODIFY on every save always hit an empty row on the legitimate paths, the id being a fresh uuid) - a foreign-owned id is still refused, and stays as it was
! The user exit is looked up once per request instead of twice: the superseded Z2UI5_IF_EXIT is asked for implementers only when Z2UI5_IF_UI5_EXIT names none, and a system that carries one class per interface now gets the current one instead of whichever sorted first across both lists
! The view model is read out of the parsed request in place: the request tree travels with the path of its MODEL node (ty_s_request-model_path) and the model service addresses the attributes below it, where the MODEL container used to be sliced out - a walk over every node of the request and a second copy of the whole delta on a mass edit
! A popup or popover binds its own copy of the response data: MAIN and a dialog used to share one JSON model data object, so MAIN's restored unsent edits showed up in the dialog and a dialog edit changed MAIN's data behind its bindings - the copy is paid per push into an open standalone slot only
! The Websocket control waits for the roundtrip in flight to land (the after-rendering hook, one tick past the busy reset) instead of polling the busy flag every 50 ms while its queue is waiting; an item fired while idle is delivered without waiting for a roundtrip that never comes
* The developer tools' code editor is sized from the viewport (calc(100vh - 17rem), full width) instead of a fixed 2000 x 10000 px: ACE laid out about 130 rows whatever the window showed and the dialog carried a permanent sideways scroller
! Less repeated work per roundtrip: the view builder appends every node to one accumulator and concatenates once (a render returned a string per node and copied every subtree once per nesting level), the default CSP meta tag is assembled once per roll area instead of on every request, the CSRF gate reads the request headers only when it is active and only as far as its rule looks, nav_app_leave reads the ancestor draft once instead of twice, a cell bind remembers the row's components across the cells of one table, and a row delta asks the type kind of a scalar column once per column - the launchpad ComponentData kept in the session is parsed by client->get( ) on demand instead of by the handler on every event roundtrip
! The frontend drops what it kept across a component teardown (the state itself with the five views and the last model, the scroll cache, the last error dump), resolves a companion control's table and a scroll item's control once per pass instead of two to four times, restores pending edits with one binding sweep instead of one per path, skips the forced refresh of SET_SIZE_LIMIT when the limit did not change, keeps one browser-storage wrapper per Storage control, and refuses a wire name that only resolves through Object.prototype (constructor) in the control-call and shortcut maps; the developer tools build the export once for the popup and its Markdown copy, mark dirty attributes by a set instead of a scan per attribute, and throttle the control picker's highlight to one lookup per frame
! The draft format changes once: the attribute rows carry their absolute type name as a string (the binding search prefilters on it, so a restored draft no longer resolves every row), and the two custom_*_back components nothing had set since the _bind parameters stopped being evaluated are gone. A draft written before the upgrade does not deserialize any more - drafts expire within hours, a roundtrip on one answers with the error page once and the next start is a fresh app
* A data reference pointed at ANOTHER attribute between two roundtrips keeps the new target across the draft: the alias pass re-checks every alias it knows and drops the ones that no longer hold, where it used to keep the first owner forever and the restore re-pointed the reference at it
* Only the target of a data reference can be an alias of another attribute - a typed table attribute that shared a data object with a reference could be paired as the alias when it sorted first, and the restore then tried to write a data reference into its parent
* What a called app writes through a reference into its caller (the factory( app = me ) shape) survives the way back through nav_app_leave( caller ): a reference that is bound on the live instance the draft is restored against keeps its object instead of being overwritten with the draft's payload - which also spares the way back through get_app( id ) a second parse of every payload
! The model service resolves a row once per pass where it resolved it per compare (the alias pass), keeps the detached references across a save and hands the same objects back to the live instance instead of parsing them (all_xml_stringify), searches a binding through a confirmed index before the full scan, applies a row delta on the request model in place, and keeps one work row per table for the old values of refused cells
! The unit tests of the model service, the bind service, the app container and the handler are restructured into one section per functionality in the order of a roundtrip (dissolve, search, model out, model in, draft; path, cell, options; xml, db, errors, model; request, response, dispatch, navigation) over one fixture that carries every attribute form - the classes that grew one per incident are deleted, their OBSOLETE notes checked against the sections first
+ Cases the sections add: a two-object cycle, a table of objects, an interface-typed reference found late, a false written back, markup and a line break through the model and the draft, mapper, filter and json flag across the draft, a cell in a helper's or a runtime-built table, a different mapper or filter refused, a filter without if_serializable_object refused, the payloads of a parsed container until the load, one container per draft and request, a refused delta cell reported through the container, two instances of one app class in the navigation stack
* The transpiled NodeJS backend (the e2e target, not a system) keeps a line break, a markup cell of a generic table and a bound attribute with a custom_mapper across the draft - three gaps of the runtime's asXML (a stripped line feed, entities resolved in the wrong order, a private attribute the heap writer cannot reach) are shimmed before the transpile and filed against open-abap
* An app called only to open a popup (client->nav_app_call to a popup app, the shape every z2ui5_cl_pop_* has) no longer empties the caller's view behind the dialog: the model of a response is pushed only into the view slots the responding app itself filled, so MAIN keeps the caller's data instead of being overwritten with a model that has none of its binding paths
* A bound attribute the draft restore could not reach any more (a host app that swapped its REF TO object sub-app for an instance of another class) no longer dumps CX_SY_REF_IS_INITIAL in the binding search of the next render - the row without a type descriptor is passed over and the data-reference compare decides
* A data reference whose target is itself a data reference (CREATE DATA mr TYPE REF TO data) keeps its data across the draft: the outer reference the save cleared is re-created on the restore, so the inner one can be put back - it used to come back initial without a word
* A draft row whose attribute the instance no longer has (a host that swapped its REF TO object sub-app for another class, a class that lost an attribute since the draft was written) is skipped by the reference restore instead of failing the load with ATTRI_GET_VAL_REF_ERROR
* A bound leaf deeper than five structure levels (sample 138: eight components down) is found by the binding search - the dissolve ran five passes and stopped, which read as BINDING_ERROR; the depth guard now counts reference hops (the only way an attribute graph can be cyclic) and the passes go on until every level is resolved
* Data references restored from the draft no longer fail silently: when a view is bound to the data, a restore that cannot read it back raises APP_STATE_RESTORE_ERROR instead of running the app on a cleared reference - which showed as a view that renders once and comes back empty on the next round-trip
+ New released JSON reader z2ui5_cl_ui5_json for app code: factory( json ) + get_string/get_integer/get_boolean/exists by path and members( ) for iteration - closes the "no portable way to parse JSON" gap of the removal plan
+ New released DDIC structure z2ui5_t_02 (name/value, both string) - the object app code points a dynamic type at instead of naming the framework's internal draft table
+ A skipped delta cell (client->get( )-t_model_skipped) now records the refused raw value and, for a nested cell, the parent row index - two components appended to z2ui5_if_client=>ty_s_model_skip
! Shell ETag strengthened: a third position-weighted accumulator makes a same-version, same-length collision (which would 304 a browser into keeping a stale shell) implausible
+ New client API families for app-owned hash routing: the hash_* methods (set, replace, back, attach_changed, routing) and app_state_* (set_active, get_href)
+ Conditional GET for the shell: the response carries an ETag and repeat loads answer 304 Not Modified
+ New view builder helper z2ui5_cl_ui5_view_builder=>escape_literal for escaping a value into a view literal
+ New HTTP POST exit config flag check_trust_forwarded_host to stop trusting forwarded-host headers
! Per-verb cache policy: the GET shell revalidates via ETag, POST responses stay no-store
! HEAD stays the session-terminate ping and deliberately answers no-store without the shell's ETag - now documented at the handler (no behavior change)
! CSP hardening: script-src and style-src are explicit, general-purpose CDN hosts dropped from the default policy
! Security response headers: Cross-Origin-Opener-Policy and Cross-Origin-Resource-Policy sent by default
* Response header names and values are stripped of CR/LF (response splitting hardening)
- z2ui5_cl_ui5_util_context=>app_get_url moved to z2ui5_cl_ui5_handler=>app_get_url. A downstream caller of the old spelling gets a compile error until it renames the class (same signature; src/00 is not the guarded API, and the shipped legacy z2ui5_cl_util=>app_get_url keeps working)
* App-state links and copied launchpad links keep a bare intent hash (opened from the tile, no app part yet) instead of landing the recipient on the FLP home page
- The corpus-count gate (npm run check:counts): a number about another repository's catalogue went red on main whenever that corpus grew by one app - too strict for what it protected. The counts in llms.txt and the build-an-app skill stay prose
* A bound scalar the client sends in a form its ABAP type refuses (`1,250.00` into a packed field) is recorded in t_model_skipped (attribute name, row 0) and keeps its value, like a table cell - it used to raise JSON_PARSING_ERROR and fail the whole roundtrip
* A sticky app under KEEP routing or with an active app-state link saves its draft, so Back/Forward, a reload and a shared link restore it instead of "bookmarked app state expired"
* A failing roundtrip in a stateful session puts the request's starting action back on the sticky handler, so the next request no longer runs against a called app the frontend never saw
* The 500 body strips app_start to class-name-safe characters, like the app-start error already did
* A percent-encoded namespace in ?app_start= (%2Fns%2Fclass) resolves to the class it spells
* nav_app_leave( r_data = an object reference ) copies the reference instead of dereferencing it as data
* dissolve( ) refreshes once per pass - a persistently failing dissolve_run no longer recurses without end
* A superseded response (a Back/Forward restore or a parallel request replaced it mid-render) leaves the busy state, its custom JS and the parked app hash to the newer request instead of ending them
* Websocket with checkRepeat = false stays closed across re-renders - "once" no longer meant once per roundtrip
* FileUploader with multiple reads every selected file, one roundtrip each (new Lib.afterRoundtrip, shared with UploadSetExt); only the first was read before
* A row delta on a bound SORTED or HASHED table is recorded in t_model_skipped, one entry per cell, instead of vanishing silently
* An app that only inherited its routing mode keeps it on a fresh route start (a reload, Back/Forward under FRESH): the explicit DEFAULT is sent on a navigation hop only
* nav_app_leave( ) without a target on an empty app stack is a no-op instead of a navigation to the app itself
* A cell binding on a table with an elementary line type raises the binding error instead of a raw CX_SY_MOVE_CAST_ERROR
* z2ui5_cl_ui5_json=>get_integer answers 0 for a JSON number outside the integer range, as documented, instead of letting the overflow escape
* c_trim strips alternating tab/space padding completely
* The view builder drops the control characters XML 1.0 forbids outright (U+0000-U+0008, U+000B, U+000C, U+000E-U+001F) from attribute values - one such byte out of a legacy long text used to fail the whole view at the XML parser
* A response model push no longer overwrites the unsent edits of an open popup/popover: the pending values are re-applied on top of the pushed data and travel with the popup's next event
* UploadSetExt hands several files picked at once to the backend one after the other - each change waits for the roundtrip of the previous one instead of being dropped by the busy guard
* Scrolling restores a sap.m.ScrollContainer through its scroll delegate (vertical), instead of scrollTo(x) moving it sideways
* Websocket leaves its give-up state when checkActive is switched back on, as its contract says
* Timer: a repeating timer with delayMS 0 fires once and logs, instead of a zero-interval loop of roundtrips
* A table cell edit of a TYPE d / t / timestamp column arriving as a delta no longer corrupts the field: the ISO spelling ajson wrote (2024-01-15, 12:30:45, 2024-01-15T12:30:45Z) is parsed back, as the whole-attribute path always did
* set_session_stateful over a nav_app_call hop: the switch compares against the state the request started in instead of toggling per app container, so two apps switching on in one roundtrip no longer leave a sticky app without a stateful session (next click: NO_DRAFT_ENTRY 500)
* An anonymous elementary data reference (CREATE DATA mr TYPE string) bound via mr->* survives the draft save; it used to be cleared and never restored
* _bind( omit_initial ) also omits an initial packed field with decimals (0.00) and an initial float (0.0E+00)
* url_param_get / url_param_get_tab: only the sap-startup-params value is percent-decoded (an encoded & or = inside any other value stays that value's own), and a literal ? inside a value no longer cuts away the parameters before it
* z2ui5_cl_ui5_json=>get_boolean answers abap_true only for a JSON boolean true, as documented (a number or a string used to read as true)
* MultiInputExt: a pick from plain suggestionItems makes its Token again (it used to be routed through the row validator and vanished)
* UITableExt: the column filter row is restored after a view rebuild on UI5 >= 1.96 as well (getFilters was asked for the Application filters, the column filter is a Control filter)
* App-owned hash routing: a Back/Forward that lands while a roundtrip is in flight is delivered once the roundtrip landed, instead of being dropped by the busy guard for good
* A backend timer tick that fires while a roundtrip is in flight waits for it instead of aborting it (Server.readHttp treats the newer request as superseding, and the user's action was lost silently)
* The controller liveness guards (timers, shortcuts, variant polls, the render phase) use a real test - membership in the current app state - instead of isDestroyed( ), which no sap.ui.core.mvc.Controller ever answers; the old guards were dead code and a variant poll chain could resolve the next app's controls after an FLP teardown
