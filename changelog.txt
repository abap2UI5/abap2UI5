abap2UI5 changelog
==================

Legend
------

unreleased
----------
* z2ui5_cl_ui5_view_builder=>escape_literal( ) keeps a doubled backslash: UI5 hands EVERY string property to the binding parser with unescaping on, brace or not, so `\\server\share` lost one backslash per pair while the helper left brace-free values untouched - the backslash is now escaped whenever present (a lone one still renders as itself)
* A generic reference that aliases a structure carrying a table component (`DATA mr TYPE REF TO data` at `{ id, t_items }`) survives the draft: the restore followed the `<alias>->t_items` row below it and re-pointed the reference at the table component on every roundtrip - only the `->*` row of a table is an alias now, like on the save side
* A row delta cell into a column that takes no value of that shape - a string or a boolean into a REF TO data, a REF TO object, an internal table or a structure - is recorded in t_model_skipped and left alone. It used to reach the assignment, which on a system is a runtime error rather than a catchable exception (OBJECTS_MOVE_NOT_SUPPORTED, a MOVE type conflict): the roundtrip dumped, and an Input bound to a REF TO string cell reached it without any crafted request. A digit-only field name, which would address a component by position, is skipped like an unknown one
* The developer tools' XML prettifier leaves `&lt;` escaped: it turned it back into a raw `<` together with `&gt;`, so a view carrying escaped markup in an attribute (htmlText, core:HTML content, a text with a comparison) was shown malformed and "Apply to App" failed on a view nobody had edited
* A user exit whose set_config_http_get raises answers a 500 with a status and a body: set_response( ) asked the exit a second time after the outer catch had already produced the 500, the exit raised again outside every TRY, and the ICF stack dumped with neither - the header read is guarded now, and the main( ) comment no longer claims the outer TRY covers set_response( )
! At most 100 event arguments per request: every object or array argument cost a slice( ) over the whole S_FRONT tree, quadratic in the count, so a 150 KB POST with 50,000 `[]` entries held a dialog work process for minutes - the 101st argument raises EVENT_ARG_LIMIT_ERROR
! A view slot the response itself displayed is not pushed the same response's model again: the backend ships MODEL with every display, and the push landed in the model just built from it - a full binding sweep on MAIN and a second deep copy of the whole model on every dialog open
! The shell's ETag is derived from the version constant, a build hash of the embedded frontend (z2ui5_cl_ui5f_preload=>build_hash, computed by tools/app2abap at generation time) and a digest of the exit config the page is built from, instead of a byte-by-byte hash of the assembled ~700 KB body: the cache that hash claimed to run behind lives in CLASS-DATA, which on stateless ICF dies with every request, so every page load paid it. A redeployed frontend with the same version constant still changes the tag
! A user exit class the lookup found but cannot instantiate (a constructor that raises, an abstract or CREATE PRIVATE class, a class left inactive by a transport) fails closed: the cause is chained into a visible 500 on the first request, where it used to be swallowed and every request silently ran on the shipped defaults - error details visible, the public CDN bootstrap, the default CSP, none of the exit's headers - while the start page still named the exit as installed
* .github/scripts/shared-file-gate.mjs answers `--manifest <consumer>` from its list before any read: the block sat inside a section callback and printed the manifest only after a successful GitHub fetch, so offline the ordinary gate report went to stdout with exit 0 and the consumers' sync workflow parsed it as file paths
* The shell's If-None-Match is compared the way RFC 7232 asks - a list, weak validators (W/"..."), `*` - and Apache mod_deflate's `-gzip` suffix is accepted too: behind a recompressing proxy the browser echoes a validator that never equalled the tag byte for byte, so the conditional GET silently degraded to a full shell transfer on every reload
* all_xml_stringify( ) puts the app's data references back when the retry fails too: only the first attempt's CATCH reattached, so in a sticky session the next request ran main( ) on an app whose generic references were initial
* follow_up_action( cs_event-set_nav_routing ) upper-cases the mode at its one write point: the frontend upper-cases before it compares, the backend compared as written, so `keep` switched routing on in the browser and left it off on the server
* The multi-message box escapes its message texts: `Enter a value for <MATNR>` lost its token to the frontend sanitizer in a two-message box while the single-message path showed it
* message_box_display( ) of an unbound object reference stays silent like every other value that carries no message; it fell through msg_get_by_oref's handlers into a describe on the null reference and ended in a 500
* decfloat16 and decfloat34 count as printable: an exception's decfloat attribute rendered as UNKNOWN_ERROR and message_box_display( lv_amount ) showed the headline `Data`
- The dead self-exclusion after the superseded Z2UI5_IF_EXIT lookup in z2ui5_cl_ui5_user_exit: the shipped exit implements z2ui5_if_ui5_exit only and is never in that list - AGENTS.md says so now instead of "the shipped exit implements both"
* Server.reset( ) makes the in-flight request stale before it aborts it: the FLP teardown's own abort was reported as a client-side timeout - BusyIndicator hidden over the next app, its state marked not busy, and the fatal "No backend response" dialog with a Retry that re-sent the dead session's body
* An unknown APP frontend action is logged like an unknown SYSTEM action; a typo in follow_up_action( ) or a wire an older frontend does not know said nothing anywhere
! The developer tools' console capture expands at most 20 items of an array and replaces the rest with a marker: the depth cap counts nesting only, so a 10,000-row table was serialized in full (millions of characters) on every console.log of a model before the 2,000-character cut
! node/setup/fetch-deps.mjs fails under CI when a pin cannot be materialized and checks that what it checked out IS the pin; it used to warn, exit 0 and let abaplint and the transpiler fall back to cloning the floating HEAD of the three upstream repositories
* dynamic-name-gate reads lower-case literals too: the start page spells its six sample tiles in lower case, so a typo there passed with a green gate
* api-snapshot accepts the first optional parameter added to a parameterless or returning-only method as additive instead of reporting the `importing` keyword as a rule-5 violation
* exception-cause-gate, assertion-gate and frozen-only-gate recognise a `TRY.` or `METHOD x.` line that carries a trailing comment; anchored on the period alone, every RAISE in such a block escaped the check
* tools/app2bsp starts the boot tail on its own line: glued onto the last wrapped bundle line, a long enough last piece failed the 255-character check with a message that blamed a frontend source line
* Two generic references at one typed table whose name sorts before them come back bound after the draft: the alias pairing named the last candidate, so MR_A->* aliased MR_B->* instead of the table and the fresh-instance load resolved MR_A while MR_B was still initial - a typed owner wins outright now
* A cell bind (_bind with tab and tab_index) passes custom_mapper, custom_filter and the omit_initial pair on to the table's bind - stored on a first bind, adopted on a later one, refused when they differ - instead of dropping them silently; the doc says json is decided on the table's bind
! The binding search resolves the rows it has not indexed yet first and re-resolves indexed rows only when that pass finds nothing: a form of k elementary attributes bound in name order paid k*k/2 dynamic ASSIGNs per roundtrip instead of k
* The user exit's context carries app_start the way the handler reads it - trimmed, upper-cased, a percent-encoded namespace unpacked - so an exit keyed on the app is not bypassed by a case change or an encoded slash; the interface doc says it is the query parameter of the current request, empty on a POST and for a hash route
! A leave hop parses the caller's draft once instead of twice and asks the database once instead of three times: db_load_by_app( ) answers with the container get_app( ) already built when that container's app IS the instance handed in, prepare_app_stack( ) no longer loads a draft for an id it has just minted (a guaranteed NO_DRAFT_ENTRY miss on every nav_app_call of a fresh app), and factory_stack_leave( ) takes whether the target was a persisted draft from that load instead of a third SELECT

! cc/Websocket clears its failure budget on the first message or after a socket that stayed open at least 10 seconds, no longer on onopen: a server that completes the handshake and closes at once (an APC whose ON_START refuses, a dropping proxy) reconnected every 500 ms with no backoff, no give-up and one error event per drop
* S_FOCUS / S_SCROLL report the bare control id in a popup and a popover too: the prefix was taken from the fragment ROOT control while the inner controls are registered under the fragment id, so the app saw `popupId--input` in a dialog and `input` in MAIN - and the SET_FOCUS / SCROLL_TO it echoed back was prefixed a second time by Fragment.byId and found nothing
* A NAMED SET_ODATA_MODEL client is destroyed with the MAIN view it was set on: the rebuild inspected the default model only, so the client survived the view and the next re-issue found nothing to destroy - the leak shape already fixed for the default model, one model name over

A draft written before the upgrade does not deserialize any more - drafts expire within hours, a roundtrip on one answers with the error page once and the next start is a fresh app
* A data reference pointed at ANOTHER attribute between two roundtrips keeps the new target across the draft: the alias pass re-checks every alias it knows and drops the ones that no longer hold, where it used to keep the first owner forever and the restore re-pointed the reference at it
* Only the target of a data reference can be an alias of another attribute - a typed table attribute that shared a data object with a reference could be paired as the alias when it sorted first, and the restore then tried to write a data reference into its parent
* What a called app writes through a reference into its caller (the factory( app = me ) shape) survives the way back through nav_app_leave( caller ): a reference that is bound on the live instance the draft is restored against keeps its object instead of being overwritten with the draft's payload - which also spares the way back through get_app( id ) a second parse of every payload

The model service resolves a row once per pass where it resolved it per compare (the alias pass), keeps the detached references across a save and hands the same objects back to the live instance instead of parsing them (all_xml_stringify), searches a binding through a confirmed index before the full scan, applies a row delta on the request model in place, and keeps one work row per table for the old values of refused cells
