==================

unreleased
----------
* Security hardening in the GET page: every < in the exit's styles_css is embedded as \x3c in the bootstrap script, so a </script> in a stylesheet cannot end the script element (defence in depth - the value is admin-supplied); the frontend's per-app shortcut and tree-state registries are prototype-less after an app switch as well
* Security hardening at the app start: a class named by the URL parameter, the hash route, the launchpad startup parameter or the start page's input is checked to implement z2ui5_if_app from its RTTI descriptor before it is instantiated, so a name that is no app loads nothing - and the error says "does not implement z2ui5_if_app" instead of "does not exist in the system"
! Security: the default CSP no longer allows 'unsafe-eval'; on UI5 1.71 to 1.82 popups preload their controls asynchronously to stay clean - only a module a popup names in a binding type or core:require still needs it there, switch it on in the user exit (see z2ui5_if_ui5_exit, content_security_policy)
- BREAKING: custom_js and title removed from z2ui5_if_ui5_exit=>ty_s_http_config - custom_js ran as inline script on the page, ship frontend code in the customer frontend BSP (z2ui5_ccc) instead; title was no longer read, an app sets it with cs_event-set_title
- BREAKING: follow_up_action( ) no longer runs raw JavaScript - a val that is not a cs_event-* name is not executed; use control_global, control_by_id or hash_back instead, or a custom control in the customer frontend BSP (z2ui5_ccc)
- BREAKING: the global `z2ui5` object is gone. No `window.z2ui5` any more - the frontend keeps its state inside core/AppState. Custom JS reading `z2ui5.oView`, `z2ui5.oConfig`, `z2ui5.developerTools` etc. no longer finds anything; `z2ui5.requestTimeoutMs` and `z2ui5.search` are no longer read
- BREAKING: `z2ui5_if_client=>cs_event-z2ui5` (frontend event `Z2UI5`, which called an app-registered function on the global) removed; frontend code an app needs ships as a custom control in the customer frontend BSP (z2ui5_ccc)
- BREAKING: the obsolete popup `z2ui5_cl_pop_js_loader` removed from src/99/02
- BREAKING: the `z2ui5.Util` and `z2ui5.Formatter` globals and the deprecated `z2ui5/Util` module removed; bind the date helpers via core:require of `z2ui5/model/formatter` (UI5 1.74 and later)
! The backend GET page hands its settings (checkLocal, ccResourceRoot, cccResourceRoot) to the component as component data instead of a global
! The framework's own views and popups get component-prefixed ids: the main view is `<component>---mainView` instead of `mainView`, the popup/popover fragments `<component>---popupId`/`popoverId`, and the fatal-error overlay `z2ui5ServerErrorContainer`. Control ids an app declares and resolves (control_by_id, focus, scroll) are unchanged; only CSS or scripts matching the full rendered DOM id (`#mainView--...`) need the new prefix
+ Several z2ui5.Component instances can run side by side on one page: the frontend state is per component (core/Context.js, one context per component) instead of a module singleton that the last instance reset for the first - a launchpad in keep-alive mode or a host creating the component twice no longer corrupts the first instance. What stays page-wide by nature (the URL hash, title and favicon, the global BusyIndicator, the devtools console capture) is listed in Context.js
! Frontend-internal API change for custom-control authors reaching into core/: the state is `Context.of(this)?.state` instead of `AppState.state`, Lib.registerCallback/unregisterCallback/cancelPendingTimers and the ViewSlots/Server/Router/Session/ScrollFocus/ErrorView functions take the context first; Lib.hookCallback, Lib.afterRoundtrip, ViewSlots.byIdOfOwner/trackedModel/markChanged are unchanged, and Lib.logError's ring is Lib.errors
* Security hardening in the frontend: OPEN_NEW_TAB opens the tab with noopener,noreferrer; cc/History refuses a search value that does not start with "?" (it rewrote the path); the wire-keyed AppState records (timers, shortcuts, viewSizeLimits, treeStates) are prototype-less
! Frontend cleanup after the review: cc/Dirty installs the unload prompt as a beforeunload listener (the assignment to window.onbeforeunload overwrote a host page's handler); MultiInputExt, SmartMultiInputExt and UploadSetExt detach their handlers from the target control in exit( ); cc/Geolocation fires its error event (code 0) when the browser has no Geolocation API instead of staying silent; cc/Info reads the device model through its own getModel, so it works inside a popup; the session block's send latches reset on the component teardown
