abap2UI5 changelog

Legend

unreleased
----------
* filter_get_token_t_by_range_t (z2ui5_cl_ui5_util_context): a range on a numeric field gives tokens with the number as it reads - =42 and -5...10, not =42 with a trailing blank and 5-...10
* _bind( val = ... json = abap_true ): a string that holds no JSON yet - initial, or cleared - travels as null. It was refused like a broken one, and since the model is serialized on every roundtrip, the app failed with "Json parsing error" on every request until the string was filled (a card manifest loaded later)
* View builder: a NUL character (U+0000) in an attribute value is dropped with the other control characters XML 1.0 cannot carry. It stayed in the view, and the browser's XML parser refused the whole view
* MessagePopover link policy RELATIVE_ONLY (CONTROL_BY_ID setAsyncURLHandler) asks the URL parser whether a link leaves the app. A pattern on the spelling let through what the browser reads as another host or scheme - /\evil.com, \\evil.com, a leading control character, a line break inside javascript: - and a message description could carry a working link off the site
* URLHELPER REDIRECT with NEW_WINDOW opens the target with noopener,noreferrer. URLHelper.redirect opens it without on UI5 1.71 - 1.83, and since this redirect may leave the origin, the foreign page got window.opener and could navigate the app's tab
* Error dialog: an error text with braces - a JSON snippet, a binding error - is shown as it is. Each line was handed to its Text as a setting, which UI5 reads as binding syntax: {...} vanished, {= } was evaluated, and an unbalanced { threw, so the user got the raw fallback overlay
* Start page: the sample repository links are written as literal values. They carry the page's own query and hash, where a browser leaves { and } unencoded, so a crafted link read them as a binding and could break the start page
* Message box: data with a column called ID - the key of most business tables - is shown as data again. client->message_box_display( ) took any ID for a T100 message class, assembled `I:0001:` per row and showed "2 Messages found" instead of the table; a message is built from a class only together with its number now
* Message box: a negative number shown as data carries its sign in front - -5, -12.50 - instead of behind it (5-, 12.50-)
* check_queue_last: a keystroke typed into a popup that the response then closed is dropped, as documented. The popup's controller outlives the popup, so the check let it through, and an event for a closed screen went out without a model
* Developer tools: the history and the Log tab record the messages of message_toast_display and message_box_display - only the rarer follow_up_action( control_global ) form was read. The model diff compares the last two responses that carried a model; a roundtrip that changed nothing showed the whole previous model as removed. The Registry tab lists an eF( 'CONTROL_BY_ID', ... ) under its own name instead of under the event of a later eB, which went missing
* Custom control z2ui5.cc.UITableExt: the column filters and the sort order are re-applied after a view_display - its main case. The snapshot was kept on the companion control, which the rebuild destroys with its view; the new one had read nothing and applied nothing, and the table came back unfiltered and unsorted. It is kept on the component's context now, like cc/Tree's expansion, and dropped on an app switch
* File uploads (z2ui5.cc.FileUploader, z2ui5.cc.UploadSetExt): a file that finishes reading while another roundtrip is running - a click, a timer tick, a websocket message - waits for it. Its event went into the busy guard and was dropped, and the next file overwrote it: of three files picked, one could silently never arrive
* Custom control z2ui5.cc.MultiInputExt: a token built from a picked suggestion row or item takes the cell text as it is. Handed to the Token as a setting, the text was read as binding syntax - "Pump {X}" lost its {X}, "A{1" threw and the pick made no token at all, a backslash disappeared
* Navigation: a bound value the caller changed right before nav_app_call reaches the browser on the way back, also when the request that made the hop carried user input. That input cleared what the framework remembers of the browser's model, the hop saved the caller without it, and on the way back the caller's current state counted as what the browser shows - a caller that left its view standing and re-displayed nothing kept showing the old value
* Model: an instant with a fraction of a second bound to a short TIMESTAMP is cut to its second. The assignment rounded it, and 12:30:59.6 became 20240115123060 - second 60, a value no timestamp has. A TIMESTAMPL keeps the fraction as before
* client->get_app( client->get( )-s_draft-id ) answers the running app. That id is the one of the roundtrip in progress, whose draft is written only when it ends, so the call raised NO_DRAFT_ENTRY_OF_PREVIOUS_REQUEST_FOUND for an id the interface documents
! z2ui5_if_client: the documentation of app_state_set_active and app_state_get_href says what a shared link does. A draft belongs to the user who created it and expires after a few hours, so the link restores the state for that user; another user, or a link whose draft is gone, starts fresh with a toast. It promised that a shared link restores the exact state for anyone
* Developer tools: the console log and the roundtrip history are carried across a reload again. The component's own pagehide listener tore the component down first, and its exit took the tools' pagehide listeners off before they had run - only a page entering the back/forward cache ever kept them
* Formatters: DateAbapDateToDateObject and DateAbapDateTimeToDateObject read a date bound straight from a DATS field - the model carries it as YYYY-MM-DD, and it always came out as no date - and a TIMS time as HH:MM:SS, which came out as an Invalid Date. DateCreateObject reads a bare YYYY-MM-DD as the local day; it was UTC midnight, the previous day anywhere west of Greenwich
* Model size limits: a limit an app set with cs_event-set_size_limit no longer applies to the next app after a navigation - the new app's tables were capped by a limit it never asked for
* @abap2ui5/node-runtime: abap2ui5-transpile runs the transpiler through npx on Windows. Without @abaplint/transpiler-cli in the project it stopped with spawnSync npx.cmd EINVAL - Node refuses to start a .cmd without a shell
* @abap2ui5/node-runtime: abap2ui5-own-apps no longer copies the libraries' source maps into the host's apps folder. The package ships its output without maps, so every library map of the host's transpile was taken for the host's own - some 470 files
* Keyboard shortcuts: a shortcut registered for the POPUP or POPOVER slot (follow_up_action( cs_event-keyboard_shortcut ) with that scope) sends the dialog's model. It ran on the MAIN controller that registered it and sent the MAIN view's edits only, so what the user had typed into the dialog did not reach the backend - the dialog's own Save button sent it
* Messages: RAP rows carry their element and action again (t_meta element / action). %ELEMENT-<field> and %OP-%ACTION-<name> were looked up among the row's own component names, which never contain a `-` - they are components of the nested structures %ELEMENT and %OP-%ACTION - so neither was ever found
* Messages: the types A (abort) and X (exit) are shown as errors, not as information
* Messages: a structure with a plain field named ITEM - a position number - is no BAPI envelope. Its ITEM value became the whole message and the other fields were dropped; only an ITEM that is a table, a structure or an object is followed now
* Custom control z2ui5.cc.ExcelBridge: text that only begins with an ISO date ("2024-01-15 delivery", a document number "2024-01-15-0001") is written as text. It was written as that date and the rest of the text was lost. A timestamp with fraction, Z or offset is still a date
* Custom control z2ui5.cc.ExcelBridge: available turns true when the host page loads Office.js after the control's first rendering, on its next rendering. It was asked once, and stayed false for the life of the control
* Custom control z2ui5.cc.Focus: the caret of the field the user just left is no longer applied to the field the backend moves the focus to. It overrode the requested selection - a select-all came out as a caret at the end
* Custom control z2ui5.cc.CameraPicture: cancelling the camera dialog while the browser's camera permission prompt was still open and opening it again left the first camera stream running once access was granted - until the page was closed. The stream of an earlier opening is stopped now
* Binding: a structure with an INCLUDE TYPE ... RENAMING WITH SUFFIX can be bound. Its components are named <component><suffix>, but the framework's component list reported the bare include names, so every binding below such an attribute failed with "No class attribute for binding found" - and since the failed lookup aborted the whole pass, so did the bindings of unrelated attributes sorting before it; a table whose row type has such an include failed the same way for its cells
* Draft restore: a REF TO data component of a structure that a generic reference aliases (mr_alias = REF #( ms_nested ), ms_nested-r_val a REF TO data) keeps its target. The restore followed the component's row under the alias like an alias of its own, and once mr_alias pointed at ms_nested again both sides named the same variable - r_val came back pointing at itself and its value was gone. It happened when the draft was saved by the roundtrip that first saw the attributes (an app that had not bound anything yet)
* App state: a bookmark #/z2ui5-xapp-state=<id> restores its app also when the URL carries no ?app_start= - client->app_state_get_href( ) keeps the page's own query, and an app reached by navigation (from the start page, by nav_app_call) has none, so the link opened the start page and dropped the saved state without a word. When the draft is gone such a link lands on the start page with the "Bookmarked app state expired" toast
* Hash navigation: the HASH_BACK frontend event with a fallback hash takes the fallback once every hash this page load pushed has been stepped back over. It counted pushes and never Back steps, so on a page opened from a bookmark the second in-app Back called history.back( ) and left abap2UI5 instead of going to the fallback
* Event arguments: a Date passed on its own - ${$parameters>/startDate} of SinglePlanningCalendar.cellPress, the from of DateRangeSelection.change - arrives as its local day (2018-07-09T00:00:00), as a Date property of a control already did. It went out as the UTC instant (2018-07-08T22:00:00.000Z), so east of Greenwich an app reading the first ten characters got the previous day
! Roundtrip monitor: off until the user exit switches it on. z2ui5_if_ui5_exit=>ty_s_http_config_post has a new field check_monitor_active, abap_false by default; only when set_config_http_post sets it to abap_true does abap2UI5 look up and call a class implementing z2ui5_if_ui5_monitor. Before, an installed monitor was called right away, and a syntax error in it or in any class it uses - a short dump no CATCH stops, unlike an exception, which the monitor's fail-open already caught - answered every abap2UI5 request with a 500: a half-activated pull of abap2UI5-addons/admin-cockpit showed "Syntax error in program Z2UI5_CL_COCKPIT_SETUP" for every app. An installation with a monitor adds cs_config-check_monitor_active = abap_true to its exit's set_config_http_post; the switch is read on every roundtrip, so switching it off takes effect at once. z2ui5_cl_ui5_srv_monitor=>set_monitor( ) - for a host without a class repository and for tests - is not affected
+ Custom control z2ui5.cc.ExcelBridge: an app running in the task pane of an Excel add-in talks to the workbook. write( ) puts the bound rows (an ABAP table) into the sheet - columns picks, orders and labels the fields, target is a cell address, selection or newSheet (with sheetName), asTable makes it an Excel table with a header row, numberFormats formats numbers and dates - and fires OnWritten with the address; read( ) puts the selected range into the bound selection as rows of COL1, COL2, ... with its address and fires OnRead; selectionChange (off by default) fires OnSelectionChange with the new address. An app calls write and read as a frontend action on the control's id: client->follow_up_action( val = client->cs_event-control_by_id t_arg = VALUE #( ( `excel` ) ( `write` ) ) ). Strings are written as text, so leading zeros stay and a string starting with = is never a formula; numbers stay numbers, ISO dates become Excel dates and come back as ISO dates. More than maxCells cells (20000 by default, 100000 at most), an invalid target or a protected sheet fire OnError with message and code, and nothing is written. The control uses the Office.js the add-in's host page loads (window.Office, Excel.run after Office.onReady) and never loads it; without it - in a plain browser - it renders an invisible placeholder and write and read fire OnError, so the same view runs unchanged. available turns true inside Excel, for the visible of the app's Excel buttons. Use it with the view builder: ns z2ui5, xmlns:z2ui5="z2ui5.cc"
* Fallback error overlay: the keyboard focus stays in it when the page behind moves the focus on its own. The raw overlay - shown when UI5 cannot render the error dialog - kept only the Tab key inside, so a starting app focusing its first input (sap.m.App) or running a SET_FOCUS after the overlay had opened took the focus out of the modal overlay for good, and Enter or Space then acted on the broken page behind it. A focus that lands outside now goes back to the overlay button that had it last; one that lands in another dialog is left there. This was also what made the overlay's focus checks in the WebKit and Firefox browser tests fail now and then
+ Claude Code plugin: a lint-on-edit hook and the /abap2ui5:add-ai command. After the agent edits or writes a *.clas.abap file, the hook runs the abap2UI5 linter's static check (no render gate, well under a second) on that file and hands its errors and warnings back to the agent with rule id and file:line, under the project's abap2ui5lint.jsonc - only in a project that already has @abap2ui5/linter installed (an app-template project does), silent everywhere else, nothing downloaded; ABAP2UI5_LINT_HOOK=off in the settings' env switches it off. /abap2ui5:add-ai adds a chat or a summarize-this-data panel to an existing app the way the samples do it (Z2UI5_CL_SMP_APP_540 and 541 with a local provider, samples-stack package 10 with a real model): a provider interface with a local stub first, the answer in a second roundtrip behind a busy state, the data sent capped and cleaned, then the switch to the samples-stack LLM classes with endpoint and key kept out of the code
* @abap2ui5/node-runtime: stateful sessions. An app that called client->set_session_stateful( ) answered every later request of every client - the framework keeps the sticky handler in class-data, one per roll area on an SAP system and one per process in Node, and open-abap's shim made set_session_stateful( ) a no-op - and before it got that far it was answered with a 500, because the framework's ICF cookie-to-header transform called an HTTP-entity method open-abap does not implement. The host is the session layer now, as the ICF is on an SAP system: it keeps the sticky handler under a session id of its own (sap-contextid, a header when the request asks for it - the UI5 frontend does - else an HttpOnly cookie), puts it back for that session's requests only and clears it after every request; set_session_stateful( abap_false ), the frontend's terminate ping and 30 idle minutes end a session, at most 1000 are kept. A forged sap-contextid is no session and is no longer echoed back. New exports withSession( ) (for a host that calls the shim itself; its owner option binds a session to a user), configureSessions( ) and sessionCount( )
* @abap2ui5/node-runtime: one request at a time in the framework. createHandler() - and so createApp(), serve() and npm run express - queues the requests, as one work process takes them. On an SAP system every request has a roll area of its own; in a Node process the framework's per-request class-data (the user exit's request context, the app-load buffer, the sticky handler), sy and the one open database transaction exist once, and so does the static server object of open-abap's express shim, whose request and response every run swaps. That held only while no request handed the event loop back - SQLite is synchronous behind its async API - and broke as soon as one really waited (WAIT UP TO, an HTTP call, a draft store on an asynchronous database): the next request then ran inside it. The new export exclusive(fn) is the same queue for a host that calls cl_express_icf_shim.run( ) itself. A request that waits holds the others up while it waits
! Error response: the request URL quoted in the first line of a 500 body ("Request failed in app ..., url ...") is stripped to the characters a URL is made of - letters, digits and / ? & = . _ - ~ : % + - the way the class name of an app start already was. A crafted request could put markup and quotes into it, and an error body that is logged, mailed or pasted into a ticket leaves its text/plain and nosniff headers behind. What a browser sends is percent-encoded and arrives unchanged. abap2UI5/protocol decision 3, backend check error.no-reflection
* Message boxes: the details of client->message_box_display( details = ... ) are on screen again on UI5 1.120 and later (the e2e tests pin 1.144). The frontend shows them unfolded and hides the "Show details" link, but from 1.120 on sap.m.MessageBox builds the details text EMPTY and fills it only when that link is pressed - so the box had an empty details area and no link left to fill it. The frontend sets the text itself now; 1.71, where MessageBox filled it at creation, is unchanged. Found by the frontend conformance suite of abap2UI5/protocol (portable.box-details)
+ Roundtrip monitor: z2ui5_if_ui5_monitor, a new interface in the released API. Implement it in a class of your own and abap2UI5 finds it like the user exit (the first implementing class by name, looked up once per roll area) and calls on_roundtrip once per POST roundtrip, after the response is built and on failure too: the app and the event, the draft ids, the user, whether the app is sticky or just started, when the roundtrip began, how long it took in total and in its three phases (load, the app's main, render and draft save), the sizes of request, response and model, the browser's own measure of the previous roundtrip (the frontend sends it as S_FRONT.MS_CLIENT_PREV) and, on failure, the full exception chain as the 500 body renders it - with the same error id - and the root cause's class. Unlike the user exit it fails open: a monitor that raises, or cannot be instantiated, costs its log entry and never the app. The LUW it runs in is described on the interface - empty for an app that is not sticky (a failed roundtrip is rolled back first, only when a monitor is installed), the app's own for a sticky one. Without an implementation nothing changes but the one lookup. abap2UI5-addons/admin-cockpit builds on it
* FileUploader: file selection updates the visible filename and enables Upload. Its internal controls now belong to the wrapper's aggregation, and the wrapper renders its own DOM root so UI5 can propagate model changes and rerender it
! @abap2ui5/node-runtime: @abaplint/runtime 2.13.96, and accelerate() installs nothing any more. The runtime itself is linear on large tables now - LOOP ... WHERE over a sorted primary key binary-searches its block (abaplint/transpiler#1950) and CP compiles a pattern once (#1933) - and as fast as the fast paths accelerate() put on 2.13.93: the event roundtrip of 4000 rows takes 2.0 s, 2.5 s with the fast paths before, 28.4 s without. accelerate() and RUNTIME_VERSION stay exported, and the ./accelerate subpath with them, for the hosts that call it: it returns true on a runtime from 2.13.96 on, and false with one warning on an older one an overrides entry forces in. npm run unit:accelerated is gone with the fast paths
* Embedded mode: an embedded app no longer sets the host's page up as a mobile app. sap.m.App - the frontend's root - runs sap/ui/util/Mobile.init( ) when it is created, once per page with the settings of whoever calls first, and on a host page without a sap.m.App of its own that put height: 100% on <html>, a viewport meta tag that disables zooming and a format-detection meta tag on the host's page - and on an iPad took its scrolling (position: fixed on <html>) and hid the browser's UI. An embedded component makes that call first now, with everything off: a host that has made it already sees no change, a host without one keeps its page. What stays, on a phone or tablet, is the web-app-capable meta tag sap.m.App sets on every rendering (found by the review of abap2UI5/embed-control)
* Embedded mode: the custom controls of z2ui5_cci and the customer's own frontend artefacts of z2ui5_ccc load when the page reaches the system through a proxy that puts it under a path prefix of its own - the destination proxy of SAP Build Work Zone (https://<site>/dynamic_dest/<name>/sap/bc/z2ui5), an approuter route. The bundle (?z2ui5-bundle) handed the two BSP roots over as the system's absolute paths, which the page requested on its own origin, where nothing is - an embedded app naming a control of either BSP failed to load it. The z2ui5/embed module now also says which path the node has on the system (nodePath), and Component.init puts what the host's endpoint has in front of that path - the proxy's prefix, and the endpoint's origin when it is not the page's - in front of both roots. A proxy that rewrites the path leaves them as they are, and so does a page on the node's own origin
+ @abap2ui5/node-runtime: abap2ui5-transpile, a bin that is the README's "Your own apps" recipe in one command - npx abap2ui5-transpile abap apps: @abaplint/transpiler-cli at the version the package was built with (the installed one, or through npx; another version installed is refused with the install command that fixes it), open-abap-core fetched once at the commit the package records, the transpile config written, the transpile, and abap2ui5-own-apps over the output. --config runs a config of your own, --core an open-abap-core checkout of your own. Until now every host - mcp-server, cap2UI5, cap2UI5/samples - carried its own copy of those steps
+ @abap2ui5/node-runtime: TypeScript declarations for the entry point and the ./accelerate and ./compress subpaths (srv/*.d.ts, named by types on every export) - a TypeScript host, or an editor, sees the signatures of serve(), createApp(), createHandler(), initialize(), accelerate() and compress() without installing anything
! @abap2ui5/node-runtime: the package no longer carries the framework's own unit tests (output/*.testclasses.mjs, their generated runners output/index.mjs and _unit_open.mjs, downport/**/*.testclasses.abap) or the source maps of output/ - nothing a host loads or transpiles against was in them, and they were a third of the 21 MB every CAP project and every MCP user installed per release. The framework's suite runs in abap2UI5's own CI as before
+ Custom control z2ui5.cc.NativeBridgeScan: a scan button for apps running inside the abap2UI5 native mobile shell (abap2UI5/mobile-shell). It calls the shell's window.abap2ui5Native.scanBarcode( ), writes the result into value and fires OnScan; a cancelled or failed scan fires OnError with the bridge's message. Outside the shell it renders an invisible placeholder, so the same view runs unchanged in a browser (showInBrowser shows the button anyway, a press then fires OnError). Use it with the view builder: ns z2ui5, xmlns:z2ui5="z2ui5.cc"
+ Tables: copy to the clipboard with sap.m.plugins.CopyProvider (UI5 >= 1.110). Its mandatory extractData callback is now shipped as z2ui5/model/clipboard: core:require="{Clipboard: 'z2ui5/model/clipboard'}" and extractData="Clipboard.extractData" on the plugin, and each column says what it copies with the demo kit's CustomData - app:bindings (comma-separated paths, one clipboard cell each) and app:template (the text/html variant, optional). Until now the plugin threw on creation and took the view with it. Its copy button is your own Button wired with client->_event_client( cs_event-control_by_id ) to copySelectionData, which runs in the click and so keeps the browser's clipboard permission; Ctrl+C needs nothing
+ Claude Code plugin: this repository is a plugin marketplace now. /plugin marketplace add abap2UI5/abap2UI5, then /plugin install abap2ui5@abap2ui5, gives an agent the four skills (build-an-app with the app guide, view-chain-layout, abap-check, ui5-check) and the abap2UI5 MCP server (npx --yes -p @abap2ui5/mcp-server abap2ui5-mcp), plus four slash commands - /abap2ui5:new-app (an app from a plain-language description: sample catalogue first, one class and its .clas.xml, validated and screenshotted, finished with the gates), /abap2ui5:check (abaplint and the abap2UI5 linter over the changed classes, findings explained, the mechanical ones fixed), /abap2ui5:find-sample (the best three matches across the three sample catalogues) and /abap2ui5:explain (lifecycle, events, bindings and view tree of an app class) - and a read-only abap2ui5-reviewer subagent that reports findings against the four skills as file:line. Each command works with the MCP server and without it. The plugin is plugin/, its skills generated from .claude/skills (npm run plugin, gated by check:plugin); the framework itself is unchanged


2026-09-29 v1.146.0
-------------------
* Embedded mode: the developer tools of an embedded app no longer capture the host page's console and errors. Their capture wraps the page's console and listens to its window, and on a host's page that was the host's output - a host's console.error or uncaught error (with whatever secret it carried) landed in the app's Log tab and bug report, and with "open on error" opened the app's tools. Embedded, the Log tab has the framework's own error log and the backend messages
* Embedded mode: Restart in the error dialog - and Refresh in the fallback overlay, Restart in the developer tools - restarts the app in place instead of reloading the page. On a host's page the reload took the host app, and everything the user had there, with it. The failed app ends, and the app the component was created for starts again in a new session; a page of the app's own reloads as before
* Embedded mode: the frontend leaves no z2ui5 global on the host page. UI5 1.x exports every class it creates as a global, so window.z2ui5.Component, z2ui5.controller.App/View1, z2ui5.devtools.DeveloperTools and a z2ui5.cc.* per custom control appeared on every page - also after abap2UI5 had dropped its own global. On a page an embedded component runs on they are taken off again, and a z2ui5 object of the host's own keeps exactly what it held. A page of the app's own keeps them: UI5 1.71 looks a base class up by that name when something extends one of ours
* Embedded mode: a starting app no longer takes the focus from the host page. sap.m.App focused the first input of the app's first page (on UI5 1.136 every app did, hello world included), and SET_FOCUS, a CONTROL_BY_ID focus( ) and the Focus control moved it as well - also out of a host field the user was typing in. An embedded app now moves the focus only while it is in the app, or while it is nowhere and the user's last focus or click went into the app; S_FOCUS no longer reports a control of the host
* @abap2ui5/node-runtime: "Your own apps" works for a class that extends something - an exception class of the app's own, say. The README's transpile config wrote no imports, so such a class did not load; with them (addCommonJS) the class imported what it extends from the transpile's output/, which holds a second copy of every library object, and that second CX_ROOT replaced the package's - from then on every request failed. The new bin abap2ui5-own-apps keeps your classes out of the output and points their imports at the package's; the README's recipe runs it
+ @abap2ui5/node-runtime: createApp() - and so serve() and the dev server - gzips the responses, as the ICF does on an SAP system when the framework asks it to: the page shrinks from about 360 KB to 85 KB, a roundtrip's JSON by two thirds. The compressed page goes out under the ETag "<tag>-gzip", which the framework revalidates to a 304 like the plain one. compress() is exported for an express app of your own - mounted in front of createApp(), which has one, it compresses once and tags once; createApp({ compression: false }) leaves it out
+ @abap2ui5/node-runtime: a roundtrip with a large table is linear again. Two functions of @abaplint/runtime made it quadratic - LOOP ... WHERE over a sorted primary key scanned every row (once per node in the JSON serializer), and CP walked the whole rest of a string behind a trailing * (once per token in the XML parser that reads the draft) - so the event roundtrip of 2000 table rows took 22.6 s in a CAP project, 1.8 s now. initialize() installs fast paths for both that answer exactly what the originals answer, validated for the one runtime version the package pins; a host that boots through output/init.mjs itself calls accelerate() from "@abap2ui5/node-runtime/accelerate"
* @abap2ui5/node-runtime: the test apps of abap2UI5's own browser tests (ZCL_TST_*) are no longer in the package. 1.145.0 shipped ten of them in output/ and downport/ and loaded them at boot, so every host - a CAP project with @cap2ui5/cds-plugin in production included - started them on ?app_start=ZCL_TST_HOST. The pack now fails when one is left anywhere in the tarball
* @abap2ui5/node-runtime: express 4 (from 4.21) works next to express 5. The peer range named express 5 only, so npm nested a second express in every project on express 4 (a CAP project, for one), and createApp() used express 5's "/{*path}" route syntax, which matches no request under express 4. createApp() mounts the handler with app.use() now, and serve() rejects on a port that is taken instead of resolving
+ @abap2ui5/node-runtime: package.json records the open-abap-core commit output/ was built against (abap2ui5.openAbapCore), and the README's "Your own apps" checks out that commit instead of cloning whatever HEAD is that day
+ Embedded mode: a component that runs inside a page of its own - loaded through ?z2ui5-bundle (z2ui5.embed.Container of abap2UI5/embed-control), or given componentData.embedded = true by a host's ComponentContainer - leaves the URL to its host: it neither listens to nor writes the hash, and no request sends it. Before, every roundtrip ended with a replaceHash("") that took a Fiori elements object page's route away and sent the host back to its list, and a host route reading like #/app/<CLASS> started that class instead of the app the host asked for. The z2ui5/embed module of the bundle passes the flag; the page, the BSP and the launchpad run as before
+ Page transitions: view_display( transition = ... ) animates the new main view (slide, baseSlide, fade, flip, show); nav_app_leave( ), the browser Back button under hash routing and transition_back = abap_true play it reversed. Try them all with the sample Z2UI5_CL_SMP_APP_531 of abap2UI5/samples
+ @abap2ui5/bsp on npm: a UI5 app as an abapGit BSP and back. `npx @abap2ui5/bsp app2bsp webapp --name ZMYAPP` writes the BSP with its ICF nodes into a folder to push to git and pull with abapGit, `bsp2app` turns a serialized BSP into an app folder again, `check` holds the page rules - and refuses up front what the system would break (a hyphen in a file name, a line over 255 characters, a binary file). The BSP Z2UI5 of abap2UI5/frontend is written with the same code, byte for byte as before
! Default CSP: script-src carries 'wasm-unsafe-eval', so a page may compile WebAssembly - the camera scanner of SAPUI5 (sap.ndc.BarcodeScannerButton) and the BarcodeScanner of abap2UI5-addons/custom-controls decode with ZXing-C++ compiled to WebAssembly and failed with a CompileError before. 'unsafe-eval' stays out: no string becomes code. An exit that writes its own policy keeps the keyword for them
