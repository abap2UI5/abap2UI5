unreleased
----------
* language model seam: on ABAP Cloud a request that could not be sent or got no answer (a timeout) is retryable, as it is on Standard ABAP
* FileUploader custom control: fileSizeExceed fires for a file over maximumFileSize - the inner control rejected it without telling the wrapper
* UITableExt: a restored column filter is shown in the syntax the column reads back (!=v, v*, *v, from..to), so submitting it again keeps the operator
* formatter DateCreateObject: a string that is no date gives null instead of an Invalid Date
! four errors of the model service name the cause and the remedy instead of a bare code: a reference handed to _bind( ), a bound attribute that cannot be reached, and two internal serializer errors that now say they are a framework defect to report
+ docs/agents/client-api.md: the client API as a generated index - every method of z2ui5_if_client with its signature and one paragraph, the obsolete ones apart; shipped with the agent skills as references/client-api.md
! agent skills: the plugin and skill copies of abap-check and ui5-check keep a short SKILL.md with a table and carry their long sections as files under references/; build-an-app is a one-rule-per-line checklist; the app guide has the test double as code
! the plugin's lint hook says once per session when a project has an abap2ui5lint.jsonc and no installed linter - it stays silent everywhere else
! developer tools: the footer button Copy is called Copy View - it copies the view that is shown, not the report - and the export dialog has one Copy instead of Copy as Markdown and Copy as Text; the Markdown form is what Report a Bug puts on the clipboard
! developer tools: Report a Bug opens the bug report form of the abap2UI5 repository in a new tab after it has copied the report - paste it into Additional context; a link under the action bar leads to the same form when the browser refused the tab, and nothing of the session travels in the URL
* the start page names an empty icon, so the browser no longer asks the host for /favicon.ico - a 404, or a 403 in ABAP Cloud, in the console of every start; cs_event-set_favicon replaces it as before
! the system fields the framework reads for their value (date, time, user, system id, release) are read in one place, z2ui5_cl_ui5_util_context=>sy_get( ) - ABAP for Cloud Development reports the old system fields on every statement that names one, so the extended check now shows one finding per field instead of one per use; no behaviour change
* developer tools: the view XML is indented by a walk over the parsed document instead of XSLTProcessor, which every browser has deprecated (Chrome logs a [Deprecation] warning on every page that opens the tools) - once the API is gone the tools would have shown every view as one unformatted line; the output stays valid XML for "Apply to App", and malformed XML is shown as it came
* set_focus: the selection is applied to a text field that is no sap.m.InputBase as well - a sap.m.SearchField restored its own cursor position instead, so the caret of a search field the view rebuilt jumped to the front after every search
! ABAP Cloud: the default bootstrap is https://ui5.sap.com/resources/sap-ui-cachebuster/sap-ui-core.js (SAPUI5) instead of the OpenUI5 CDN - the platform sends a Content-Security-Policy header of its own whose script-src trusts the SAP hosts only, so sdk.openui5.org was refused and a default installation showed a blank page; every other system keeps sdk.openui5.org, and an exit that sets src is not touched
* launchpad: every roundtrip names the logon client (sap-client, from the page URL or the launchpad's logon system) - without it the ICF took the client from a cookie all tabs of the host share, and a tab in another client turned the next event into NO_DRAFT_ENTRY_OF_PREVIOUS_REQUEST_FOUND
! message_box_display( ): an error box is never empty or missing - type = `error` over a value with nothing to show (an empty RAP REPORTED, an empty message table, an unbound reference) shows "The operation failed, no further details available" instead of no box, and an error message without a text shows a standard text with its message class and number; every other type stays silent over empty data
! the decision what a message box shows moved into one class, z2ui5_cl_ui5_srv_message (box_resolve from z2ui5_cl_ui5_frontend, ui5_msg_box_format from z2ui5_cl_ui5_util_context)
! _bind_tab( ) is now window_bind_tab( ) and _bind_tab_row( ) is now window_get_row( ) - renamed before their first release, signatures unchanged: the windowed table is a special function with a prefix of its own; the types ty_s_bind_tab_sort / ty_s_bind_tab_filter keep their names
+ _bind( ): val and tab take a data reference as well - REF #( mt_rows ), an attribute TYPE REF TO data holding a table typed at runtime - bound as what it points to, the two forms window_bind_tab( ) already takes; a table typed at runtime no longer needs an ASSIGN just to be bound, and a reference that points nowhere raises BINDING_ERROR instead of being refused as a reference
* error texts name what they are about: a cell binding that finds no attribute names the row and the table, a failed draft update names the draft, and the log lines of the companion controls (Tree, UITableExt, MultiInputExt, SmartMultiInputExt, UploadSetExt, Geolocation, HTMLFrame) and of a failing follow-up action name their control or action
* a sticky handler releases the parsed request model too, not only the request text, once the roundtrip is answered
* custom control z2ui5.cc.ExcelBridge: a control destroyed while Office.onReady( ) was pending no longer subscribes to the workbook events
* developer tools: the Registry tab lists the onRoundtripEnd waiters
* window_bind_tab( ): an attribute refresh (a reference created late in main( ), the serializer's retry) keeps the window of a windowed table - it used to drop window size, count, sort and filter, shipped the whole table, ignored the browser's next window request and applied the next row edit by raw index into the wrong row
* window_bind_tab( ): a new sort or filter the app passes reaches the browser in the same roundtrip - an event roundtrip that displayed no view and changed no bound value sent no model, and the server computed later row edits through an order the browser did not show
* window_bind_tab( ): a window count from the browser that is no plain number (a blank inside, past the integer range) is one window instead of a 500 out of an event that runs outside every TRY
* window_get_row( ): the browser order is computed once per table and render, not once per call
* an exit returning more than 596,523 hours of draft expiry no longer overflows the cleanup into a 500 on every first start - the shipped exit and the draft service clamp it to ten years (z2ui5_cl_ui5_srv_draft=>c_max_exp_time_in_hours)
* a bookmarked draft that exists and is the user's but cannot be restored raises with its cause instead of the "expired" toast and a fresh app; a draft that is gone or another user's still starts fresh with the toast
* a sticky app's z2ui5_if_app~id_draft follows the id of every roundtrip, as it does for an app whose draft is saved
* a sticky handler releases the request body, the response and the model snapshot once the roundtrip is answered, instead of holding them in the session until the next request
* outbound HTTP (z2ui5_cl_ui5_util_http): a response body without a charset is decoded as UTF-8 instead of the ICF's ISO-8859-1 default (umlauts and every non-Latin answer of a language model came back garbled), and the client is created without a logon popup, so a 401 comes back as a 401 instead of a communication error
* z2ui5_cl_ui5_llm: only a failed send or receive is retryable - a missing or forbidden destination is not
* the GET page leaves out an exit's t_add_config row whose name is no attribute name - the escape covered quotes only, and a name with a blank or `=` rendered as several attributes of the bootstrap tag
* offline queue: kept under the endpoint without its fragment - the hash routing rewrites the fragment after the first response, and a reload looked under another key and never sent what was kept; entries kept under a fragment key before are taken over once
* offline queue: a roundtrip whose event was kept offline ends like a rendered one - timer ticks, message box answers and the next file of a multi-upload that waited for it went nowhere; the queue is sent without the navigator.onLine gate (a VPN-only or intranet host reports offline while the system answers), the replay is stamped and aborted like any roundtrip, and a Back/Forward restore waits for it
* a response a Back/Forward restore superseded no longer arms a START_TIMER into the restored app
* a table's window request and a check_queue_last keystroke kept during a roundtrip no longer overwrite each other - each has its own slot
* custom control z2ui5.cc.Websocket: a path of the system is opened where the endpoint is - another origin or behind a proxy prefix - not on the host page's origin
* custom control z2ui5.cc.HTMLFrame: the frame's load listener is added once, not on every render
+ custom control z2ui5.cc.FileUploader: maximumFileSize (MB, 0 = no limit, default) and the event fileSizeExceed - a file over it is not read into the model; z2ui5.cc.UploadSetExt honours the upload set's own maxFileSize the same way
* developer tools: the export masks the sap-contextid and every JSON value under a key that names a secret, the journey test class writes no typed password, Report a Bug says "copied" only when the browser took it, and a download's blob URL is no longer revoked before a large file was saved
+ window_get_row( val row ): the row of a window_bind_tab( ) table behind a position the browser shows - the index of a binding path an event hands over is a position in the server's sort and filter order, not a row of the table (#2962)
+ window_bind_tab( val = t_rows window = n t_sort t_filter ): a large table goes to the browser n rows at a time - the list binding of a growing sap.m.Table / List or a sap.ui.table.Table asks the framework for the next window as it grows or scrolls (a roundtrip that does not call main( )), and its sort( ) and filter( ) - the column menu of sap.ui.table, cs_event-binding_call - run on the server over all rows; edits and selections land in the row of the table they were made in; the app sets the order and the filter with t_sort / t_filter (taking effect when they change, so a view rendered again keeps what the user picked); val may be a data reference (REF #( ), an attribute TYPE REF TO data); /__WINDOW/<path>/TOTAL counts the rows the filter lets through (#2962)
- src/99/01 (z2ui5_cl_util, _db, _ext, _http, _log, _msg, _range, _xml, z2ui5_cx_util_error, table z2ui5_t_91) moved to https://github.com/abap2UI5/abap2UI5-ext - code that still uses these objects keeps working once abap2UI5-ext is installed next to abap2UI5; the table and its data stay in the system
! frontend: the ICF handler z2ui5_cl_lp_handler of every delivery branch (standard, cloud, _v2, _new) calls z2ui5_cl_ui5_http_handler instead of the frozen z2ui5_cl_http_handler (#2886) - pulling the frontend now needs a backend from 1.148.0 on; z2ui5_cl_http_handler itself stays for ICF nodes that name it
+ custom control z2ui5.cc.HTMLFrame: an app's own HTML document in an iframe under the page's CSP (no inline script runs, its styles do), and the sapevent: links and the forms posted to a sapevent: action in it as the sapevent event with action, getdata and postdata - what cl_gui_html_viewer and its SAPEVENT are in the SAP GUI
* 702 build: compiles and imports on 7.02 SP13 (#2947) - no ASSERT_TRUE/ASSERT_FALSE (the downport rewrites them into ASSERT_EQUALS), no CHANGING/EXPORTING in a chained method call, no INT8, no built-in function as an INSERT operand, no line over 255 characters, z2ui5_cl_ui5_llm_guide in statements the 7.02 class scanner takes, and no GETWA_NOT_ASSIGNED dump in z2ui5_cl_ui5_srv_model at app start; npm run downport fails on these shapes from now on
+ cs_event-set_app_full_width: the app takes the launchpad's full width instead of the shell's letterbox (ShellUIService.setApplicationFullWidth from UI5 1.133, AppConfiguration before), what a Fiori elements app gets from fullWidth in its manifest - which the one z2ui5 component cannot set per app
+ cs_event-cross_app_nav_get_links: the intents the launchpad offers the user for a semantic object (getLinks), handed back to a backend event as JSON with each intent split into semanticObject, action and params - what a smart-link popover lists, navigated to with cross_app_nav_to_ext
- the eight obsolete invisible custom controls z2ui5.cc.Timer, Focus, Scrolling, Title, LPTitle, Favicon, History and Info (deprecated in #2789) - a view that still names one fails to load; the replacements are the frontend actions cs_event-start_timer, set_focus, scroll_to / scroll_into_view, set_title, set_title_launchpad, set_favicon, hash_set( ) / app_state_set_active( ) and client->get( )-s_device / -s_ui5
* z2ui5_cl_ui5_user_exit=>set_instance( ): a subclass of the shipped exit is installed as the shipped exit, not as a customer exit the shipped set_config_http_get/post dispatch to - a subclass that did not redefine both methods recursed into itself and dumped on the first request
* a roundtrip of an app that is not sticky and raises in main( ) rolls the app's LUW back before the 500, with or without a monitor installed - the end of the ICF dialog step committed what the app had written before it raised
* set_session_stateful( abap_false ) followed by an exception in the same roundtrip: the sticky flag goes back to the request's start state, so the next event no longer runs on a stateless handler against a draft that was never written
* a bookmark restore (z2ui5-xapp-state) clears id_prev_app together with the app stack - get_app_prev( ) no longer follows a draft of the session the bookmark was made in
* Content-Security-Policy: the shell's script hash is added per directive - an exit that listed it in script-src no longer kept script-src-elem from getting it, which blocked the inline boot script
* z2ui5_cl_ui5_view_builder: a name ending in a colon or with a second colon (xmlns:, a::b) raises instead of rendering a view no XML parser reads
* z2ui5_cl_ui5_util_context=>c_escape_xml( ): U+FFFE and U+FFFF are dropped like the control characters; conv_decode_x_base64( ) / conv_encode_x_base64( ) re-raise a failing fallback with its cause
* z2ui5_cl_ui5_llm=>create_openai( ): a response whose content is null and whose message carries a refusal raises z2ui5_cx_ui5_llm as a refusal instead of "returned no text"
! nav_app_call to an app that only opens a popup: the caller's keyboard shortcuts, tree and table snapshots, model size limits and hash listener survive the hop - the frontend reset them whenever the response named another app, now only when the response replaces the app on MAIN
* Developer tools: Escape runs the dialog's close on UI5 1.71 (the escapeHandler is set in code; as an XML attribute the property is typed any there and stayed a string), so the error popup the Details action came from is shown again
* handler-queued frontend actions resolve their ${/path} arguments against the model of the slot the responding app filled, not always MAIN
- the "No internet connection" alert on an event while navigator.onLine is false - it silenced every timer tick on an intranet host the browser reports as offline; a network failure is reported by the roundtrip itself, with Retry
* Developer tools: the ABAP source and ADT links use the origin of the endpoint, not of the host page, when the component is embedded
+ release assets: backend-<version>.tar.gz.sha256 next to the prebuilt backend, verified by @abap2ui5/mcp-server
+ cs_event-offline_queue (experimental): the events an app names wait in the browser while the backend cannot be reached - kept with their model changes across a reload, sent in order once the network is back, each on the draft the previous one left; every other event fails as before. The page itself still needs the network to load (docs/concepts/offline.md)
+ release assets: abap2ui5-<version>.cdx.json, the CycloneDX bill of materials of the release - the ABAP objects and the embedded frontend with a SHA-256 each, and UI5 as the one runtime dependency, never bundled (npm run sbom; check:sbom holds the tree to "nothing third-party is shipped")
+ z2ui5_cl_ui5_llm=>guide( ): the guide to building apps (docs/agents/building-apps.md) ships in the system, in the version of the release installed - for a model that writes apps and for the AI assistants that read the system's code rather than the repository. Generated into z2ui5_cl_ui5_llm_guide by npm run guide-class
! automatic model update: the pre-main( ) snapshot the handler compares against is a copy of the bound values (table sharing makes it free for everything main( ) leaves alone) instead of a digest of the serialized model - a delta roundtrip no longer serializes the whole model before main( ) runs, and an event roundtrip without a display serializes it only when it will be sent. The digest the draft carried for it (mv_model_client_hash) is gone: a draft written by the previous release does not deserialize any more, the roundtrip on it answers the error page once and the next start is a fresh app. z2ui5_cl_ui5_util_context=>hash_string( ), which existed for that digest, is removed
* z2ui5_cl_ui5_view_builder: an element or attribute name starting with a colon, and a prefixed name next to ns (ele( n = `x:Icon` ns = `core` )), raise instead of rendering a view no XML parser reads
* z2ui5_if_ui5_llm: a temperature with a leading or trailing point (`.7`, `1.`) is refused before the request instead of going out as invalid JSON
* message box and error texts: an int8 value is printed, with its sign in front
* Developer tools: the Journey export no longer cuts a long literal inside a doubled backtick, and a Copy button pressed twice returns to its label
* ExcelBridge: a text like 2024-13-01 or 2024-01-15T10:75:00 stays text instead of becoming a rolled-over date
+ Developer tools: the Journey tab (Roundtrips, key JOURNEY) records a click-through - every roundtrip as a step with the event, its arguments, the model delta the user typed and the screen the response showed - and exports it as an ABAP Unit test class that replays the journey on z2ui5_cl_frontend_simulator (abap2UI5/headless-frontend): set_value / set_json / set_cell for the typed values, click for the event, assertions on the messages, layers, control ids and events of the screens reached. Paste it into the app's test include
+ z2ui5_if_ui5_llm: one language model seam for apps and addons - chat( ) with system prompt, conversation and options, answering text, stop reason and token usage, raising z2ui5_cx_ui5_llm; providers from z2ui5_cl_ui5_llm: create_claude( ) (Messages API), create_openai( ) (Chat Completions: OpenAI, Azure OpenAI, Ollama, LM Studio, gateways) and create_local( ) (rule-based, no HTTP, for 7.02 and tests). Keys, models and endpoints come from the app
+ z2ui5_cl_ui5_util_http=>client_request( ): outbound HTTP with header fields and a timeout, on Standard (CL_HTTP_CLIENT) and on ABAP Cloud (CL_WEB_HTTP_CLIENT_MANAGER), both named dynamically; client_call( ) goes through it and so reaches ABAP Cloud as well
! frontend/embed (the delivery branches standard_new and cloud_new): @abap2ui5/embed-control 0.3.0, and the page is handed to the app by the control's ownsPage, set in the view - the controller no longer probes the control for ownsPage or its older name ownsHash
+ coding agents: the abap2UI5 plugin for GitHub Copilot in plugin-copilot/ (copilot plugin install abap2UI5/abap2UI5:plugin-copilot) - the four skills, the five commands (also as VS Code prompt files), the abap2ui5-reviewer custom agent and the MCP server - and the four skills in the Agent Skills format in skills/ (npx skills add abap2UI5/abap2UI5), both generated from the Claude Code plugin's sources
! z2ui5_if_client: the doc on t_model_skipped, ty_s_model_skip and get( ) says what the model does - a bound scalar that will not convert is traced there (name = the attribute, row 0) and keeps its old value; it said the scalar still raised JSON_PARSING_ERROR. Documentation only, no change in behaviour
