abap2UI5 changelog
==================

Legend
------

- : removed


unreleased
----------
* Binding: a number with more digits than a double keeps (a TZNTSTMPL, DEC 21 or longer, int8, decfloat) goes out as text when its digits need it - the browser rounded it, and the next edit of any sibling field wrote the rounded value back (20240115123045.1234567 became ...045.125)
* Binding: a structure, a structure cell or a table written as one value reads an emptied date or time as initial and plain digits (yyyyMMdd, HHmmss) like a cell does - an emptied date became blanks on a system, and the structure refused every later edit; its data and object references keep what they held instead of refusing the whole value
* Binding: a row delta into a table of references to rows goes into the rows they point to, and a row no cell can go into is traced in t_model_skipped - the edit was dropped without a word
* Binding: a numeric text (NUMC) takes digits only and no more than it has places - '12a3' was stored as 00123 without a trace; refused and traced like a date that is no date
+ z2ui5_if_app: an ABAP-Doc header naming z2ui5_cl_ui5_llm=>guide( ), the guide of the installed release, for a developer or an AI assistant working in the system through ADT - the interface every app names said nothing about where the guide is
* Tooling: the downport refuses a config whose src/ glob it cannot retarget (abaplint --fix would have rewritten src/ in place), express:live answers a malformed request with 400 instead of exiting, abap2ui5-own-apps empties only a folder it wrote, and pack-npm / verify quote their arguments on Windows
* Embedded on a host page: the BUSY_INDICATOR action covers the component's own area - it blocked the host's whole page, and its hide took down the host's own indicator; hash_back is refused there - it navigated the host's history or overwrote its route
* hash_back: a push of the hash the browser already stands on counts as no history entry, and the route a nav_app_call pushes under hash_routing does - the next hash_back took the wrong branch, leaving the app or staying put
* A restart in place from the error dialog: a view of the app that ended, still being built, no longer lands over the restarted app
* Custom controls: a bundle load that never answers fails the view after 60 seconds instead of stalling every later view; SET_ODATA_MODEL builds no client for a component that went while the class loaded
* app2abap: the generated text classes keep every line within 255 characters on a line of backticks, the bundle embeds only the files git knows of a frontend kind (a .DS_Store broke it, a stray note would have shipped), and a relative sap.ui.define dependency on a deferred bundle is refused like an absolute one
* HTTP handler: every response carries X-Content-Type-Options: nosniff of its own - an exit that assigned its own security headers instead of appending, or one that raised, dropped it, also from the text/plain 500 bodies
* App start: a name that is no global class name (an absolute type name such as \PROGRAM=...\CLASS=...) is refused - it started a local app class of any program
* window_bind_tab: a sorter or filter condition whose path could not name a component, or whose operator is off the documented list, is dropped before the app sees it; the docs say to check the path and pass the values as host variables
* 500 body: the event name and the draft id of the context line go through the same character allow-list as the url and app_start - a crafted event name was quoted as sent; security.md said the url was never reflected, it is, filtered
* Language models: a message with a role other than user or assistant is refused - a bound conversation let the browser add a system turn that overrode the app's system prompt; the guide says to keep the conversation passed to chat( ) unbound
* DOWNLOAD_B64_FILE: a file name with an active extension (.html, .hta, .svg, ...) is refused whatever the data: type, and a URL of another origin opens in a tab of its own - the browser navigated the app's tab to it
! Error overlay: no Retry after a 504 or the client timeout - the backend had the request and may have run it, and Retry ran the event a second time (a document posted twice); the overlay says to check the result instead
* Developer tools: Report a Bug, the history download and the ABAP Unit export mask secrets in every view - a value bound to a name like PASSWORD went out in the Bindings, Journey and Model Diff text, in the raw history JSON, and in structure fields and table cells of the unit test
* Developer tools: "Copied" only when the clipboard took it - a refused or empty copy said Copied anyway
* After a fatal error nothing is sent until Retry or Restart - a shortcut, a hash change or a websocket message still sent a roundtrip behind the error dialog, and Retry then replayed an older draft
* Embedded on a host page: app shortcuts leave keystrokes outside the component to the host - Ctrl+S or Enter in a host field was taken by the app
* Clipboard: the html flavour of a table copy escapes the cell values - a value with < or & broke the pasted table
* Launchpad: one link parameter that is no valid percent-encoding no longer drops every link of CROSS_APP_NAV_GET_LINKS
* A view that names a library being loaded waits for that load instead of fetching its controls one module at a time; the variant wiring skips a view replaced while sap.ui.comp loads
* HTMLFrame: a submit button's formaction / formmethod decide the event, as in a browser - every button raised the form's own action
* Websocket: the reconnect budget is kept per URL across view rebuilds - an app answering a failed connect with view_display reconnected in a loop
* FileUploader: direct upload reads the file on change - it first posted the whole file to the page's own URL
* SmartMultiInputExt: range data is applied when the inner controls existed before the companion attached - it waited forever
! rename.mjs and update-deps.mjs have one source, .github/shared/, checked by check:shared in every repository that carries a copy; the rename survives @abaplint/cli 2.120.122, which moved the output of a run config below .github
* 702: z2ui5_cl_ui5f_bundle, z2ui5_cl_ui5f_cc and z2ui5_cl_ui5f_devtools compile on 7.02 again - the generator joined up to 441 literals with && in one statement, more than the 7.02 class scanner takes; it closes the statement every 80 operands now, and check:abapgit fails a statement in src/ over 90 (#3074)
* Drafts: a table that a public REF TO data attribute got after the first roundtrip, and that is never bound, is kept in the draft - it was gone on the next roundtrip
* Binding: a bound attribute that can no longer be reached (its reference was cleared) no longer makes every roundtrip send the whole model and mark the client model stale after nav_app_call( )
* Windowed tables and z2ui5_cl_ui5_test: sorters and response actions are read in array order - from ten entries on, the eleventh came before the third
* Language models: a temperature with a leading zero (01, 00.5) is refused like any other malformed one - it went out as a JSON number no parser accepts
* Messages: a MESG- or T100-shaped row (fields ARBGB, TXTNR) keeps its message class and number - both were lost
! Language models: the Claude provider reads an error that is a plain string (Ollama's shape); the OpenAI-compatible provider names its endpoint in the texts for a missing model and an empty message, as the Claude provider does
* z2ui5_cl_ui5_util_http on ABAP Cloud: the client, request and response are called by their interface names (IF_WEB_HTTP_CLIENT~EXECUTE, ...) - a bare name resolved only where the implementing class declares an alias. From abap-util
! conv_get_string_by_xstring( ): bytes that are no UTF-8 raise INVALID_UTF8 instead of UNSUPPORTED_CODEPAGE_API. From abap-util
* tools/bsp_rename: a namespace that holds the old name (/Z2UI5/) keeps it in the urls of its ICF nodes and gets its namespace nodes - the node came out as /sap/bc/ui5/ui5 and without them
* Range tokens: a CP / NP range row whose LOW already is a pattern (abc*, *abc) renders as that pattern - the token template wrapped it in asterisks once more (*abc**). From abap-util, where a pattern token is now stored as typed
! ABAP Cloud: the branch cloud carries the whole repository, as 702 does, and is rebuilt on every push to main - always one commit ahead of main, never behind. An installation pulls src/ as before
* 702: the test include of z2ui5_cl_ui5_srv_model activates on 7.02 - the downport declared 14 field symbols LIKE LINE OF a generically typed table ("<TAB> is a generic type"), which took the whole class pool down; the rows are assigned first now, and check-generic-like also catches FIELD-SYMBOLS ... LIKE, not only DATA ... LIKE
+ build-rename also builds the renamed 7.02 installation: rename_<name>_702 is the renamed tree run through the same downport as the branch 702 (npm run auto_downport, without the BSP) and linted with the 702 config before it is pushed; the input with_702 (default on) switches it off. There is still no renamed variant of the branch cloud
+ Agent guide (docs/agents/building-apps.md, llms.txt, z2ui5_cl_ui5_llm_guide): a table of the names that changed for readers who know the old API, the addons and where their catalogue is, and markers around the passages app-template's AGENTS.md carries as essentials - the guide itself moved there into one file of its own
! Agent guide: the names that changed are reported by the linter from 0.13.0 on - removed-api names the release and the replacement, and a class on the legacy z2ui5_cl_xml_view builder is judged by every rule that needs no view. The framework's own apps are checked with that release

2026-11-25 v1.151.0
-------------------
! One pull is a running installation: the ICF node /sap/bc/z2ui5, its handler z2ui5_cl_ui5_icf_handler (was z2ui5_cl_lp_handler) and the launchpad BSP Z2UI5 are part of abap2UI5 (src/03). abap2UI5/frontend is retired - remove it from abapGit without deleting its objects, then pull

+ Navigation: check_on_nav_back( ), nav_app_call( tag ) with get_nav_tag( ), check_nav_pending( ), and keep_messages on nav_app_leave( ) / nav_app_call( )
+ Timers: timer_set( ) / timer_stop( ) declare a timer the framework arms whenever the app gets the screen; START_TIMER can repeat and STOP_TIMER ends it. A tick that changes nothing writes no draft, and a click during a tick is no longer dropped
+ z2ui5_cl_ui5_test: a public test harness that drives an app from ABAP Unit through the real framework, one roundtrip per call
+ Binding: attributes an interface declares and fields with a namespace (/ABC/FIELD) bind; z2ui5_cl_ui5_view_builder=>component_path( ) returns the row-relative path of such a column

! Speed: the frontend is a cached, minified bundle that loads while UI5 boots (first view about 0.5 s earlier), the custom controls load only when a view uses one; drafts are smaller and pruned per chain (exit field draft_keep_per_chain, 2 by default)
! BREAKING: wire protocol 3 (VIEWS / NAV / ACTIONS, S_FRONT.ROUTE, event flags as one object) - apps change nothing, tools that read the response do. Windowed tables are app-driven (t_sort, t_filter and window_get_row( ) are gone), hash_set( ) / hash_replace( ) write only for an app with a hash listener, an own draft store implements prune_chain( ) and touch( )
- BREAKING: z2ui5_cl_http_handler (use z2ui5_cl_ui5_http_handler), z2ui5_if_exit (use z2ui5_if_ui5_exit), _bind_edit( ) (use _bind( )), the five *_model_update( ) methods (delete the calls) and the experimental offline queue. z2ui5_cl_xml_view(_cc), z2ui5_if_types and the z2ui5_cl_pop_* popups moved to abap2UI5/abap2UI5-ext, with the legacy utilities
