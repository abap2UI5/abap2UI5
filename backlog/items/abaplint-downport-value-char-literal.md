# Downport: `VALUE #( ( 'lit' ) )` into a table of `c LENGTH 72`

## What happens

A table of `c LENGTH 72` filled with a constructor expression of char
literals:

```abap
DATA lt_src TYPE STANDARD TABLE OF c72 WITH EMPTY KEY.  " c LENGTH 72
lt_src = VALUE #( ( 'REPORT ztest.' ) ( 'WRITE 1.' ) ).
```

abaplint 2.120.120's downport (702 target) rewrites the rows into an
`INSERT` of the literal into the table, which its own `check_syntax` then
rejects as "Types not compatible". 2.120.92 produced a version that compiled.

## Expected

The downport keeps the line type, e.g. an intermediate `DATA ls_row LIKE LINE
OF lt_src. ls_row = 'REPORT ztest.'. INSERT ls_row INTO TABLE lt_src.`, as it
does for other row types.

## Reproduce

    cd abap-cloud-gui && npm ci && npm run check:702
