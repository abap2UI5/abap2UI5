# Needless code: CLEAR right after DATA, me->, empty class sections, lang="en" in ABAP Doc

All four are deletions with no behaviour change; one rule, one option per check.

Merged on 2026-10-12 from the items `abaplint-clear-after-declaration`, `abaplint-unnecessary-me`.

## Report CLEAR of a variable as its first use after the declaration

```abap
DATA lv TYPE i.
CLEAR lv.
rv = lv.
```

**Proposal.** Report CLEAR/FREE of a local, non-static variable that is not read or written between its declaration and the CLEAR, outside loops.

**Not reported.** STATICS; variables in loops (the CLEAR runs every pass); CLEAR … WITH.

## Report unnecessary me-> self references

```abap
me->mv_count = 1.
me->run( ).
```

Instead:

```abap
mv_count = 1.
run( ).
```

**Proposal.** Report me-> before an attribute or method when no local variable or parameter of the same name exists; quick fix removes it.

**Not reported.** me-> needed to address an attribute shadowed by a local (that is shadowed-variable's case).

## Remove empty PROTECTED/PRIVATE SECTION from a class definition

```abap
CLASS zcl_x DEFINITION PUBLIC.
  PUBLIC SECTION.
    METHODS run.
  PROTECTED SECTION.
  PRIVATE SECTION.
ENDCLASS.
```

**Proposal.** Report a SECTION statement with no components before the next SECTION or ENDCLASS; quick fix deletes it.

**Not reported.** Classes generated by a framework that expects the sections (option).

## Remove lang="en" from ABAP Doc

```abap
"! <p class="shorttext synchronized" lang="en">Run</p>
```

**Proposal.** Report lang="…" in ABAP Doc short texts; the attribute is ignored for synchronized texts. Quick fix deletes it.

**Not reported.** -

**Where.** a new rule, one option per check. **Effort:** S.
