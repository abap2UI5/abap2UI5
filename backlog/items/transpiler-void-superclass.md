# transpiler: `unknownTypes: "runtimeError"` does not cover an unknown super class

`unknownTypes: "runtimeError"` exists so that a project with references to
objects the transpiler does not have still builds: the transpiler sets the
errorNamespace to a pattern that matches nothing, every unknown type becomes
void, and a statement using one throws `Void type: ...` when it runs.

A class whose super class is unknown is not covered:

```abap
CLASS zcl_void_super DEFINITION PUBLIC INHERITING FROM /iwbep/cl_mgw_push_abs_data CREATE PUBLIC.
  PUBLIC SECTION.
    METHODS hello RETURNING VALUE(rv) TYPE string.
ENDCLASS.
```

`Transpiler.validate( )` reports `check_syntax, Super class
"/iwbep/cl_mgw_push_abs_data" not found or contains errors` and throws - the
run writes nothing, not even the classes that do not touch it.

**Expected.** In runtimeError mode the class is transpiled as if it had no
super class (or with a stub super class), and what reaches the missing part -
`super->` calls, inherited attributes, the constructor chain - throws
`Void type: <super class>` at run time, like every other void type.

**Why it matters.** Code generated by SAP tools (SEGW data and model provider
classes, RAP behaviour pools on frameworks that are not there) sits next to
plain classes in the same package; one such class keeps the whole package out
of a transpiled test run.
